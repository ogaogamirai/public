Unit 1 — システム思考の入り口：一直線？ それとも丸い？

対象: 中学2年生 ゴール（L3 Teach-Back）: 「一直線の考え方」と「丸い（循環する）考え方」の違いを、自分の言葉で人に説明できる 所要目安: 15〜20分

1. Hook — まず2つの場面をイメージしよう

場面A ドミノ倒し

ドミノを倒し始めると、パタパタパタ…と次々に倒れていきます。 最後の1枚が倒れたら、おしまいです。

場面B ブランコ

こぎ始めると、ブランコは前後に揺れます。 揺れが止まりそうになったら、もう一度こぐと、また大きく揺れます。

さて、この2つはどこが違うでしょう？

ヒント: 「おしまいがあるかどうか」に注目してみよう。

  • ドミノ倒しは 原因→結果で終わる
  • ブランコは 結果が原因に返ってくる

この「結果が原因に返ってくる」ことを、ぐるぐる回る＝循環（ループ） といいます。

2. なぜこれを学ぶのか？（Value）

私たちは普段、物事を「AならばB」という一直線で考えがちです。

勉強した → 成績が上がる。（おしまい）

でも、現実はそんなに単純ではありません。

勉強した → 成績が上がる → 「やればできる！」と自信がつく → もっと勉強する → さらに成績が上がる → …

結果が原因に返ってきて、ぐるぐる回っています。

これを学ぶと、物事がなぜ良くなっていくのか・なぜ悪くなっていくのかが、ただの結果を見るよりもずっと深く分かるようになります。これが「システム思考」の入り口です。

3. この教材を最後まで学ぶと、どこまで分かるようになる？（ゴール像）

「システム思考」を全部で8つのユニットで学びます。最後まで学ぶと、こんなことができるようになります。

レベル できるようになること 例
Unit 1〜4（見る力） 物事が「なぜそうなるのか」を、ぐるぐるの構造で説明できる 「風邪が流行るのは、うつす→増える→さらにうつす、のループがあるから」
Unit 5〜6（直す力） 問題の「どこを直せばいいか」を見つけられる 「部活で記録が伸びない原因は、練習メニューのこの工程がボトルネックだから」
Unit 7（総合力） 構造を見て、制約を直し、改善案を出せる 学校の行事や係の仕事を、根拠つきで改善提案できる
Unit 8（抽象化） 学んだことを自分たちの言葉でまとめ、新しい場面で使える テスト勉強で学んだループの型を、部活・友達関係・将来の仕事に応用できる

つまり、ゴールは「知識を覚えること」ではありません。 身の回りの出来事を「ぐるぐるの構造」として見て、「どこを直せば良いか」を自分で判断できる、という一生ものの考え方を手に入れることです。

4. 2つの考え方を比べてみよう（Reveal）

一直線 丸い（ループ）
形 原因 → 結果 原因 → 結果 → また原因に返る
終わり ある（結果でおしまい） ない（ぐるぐる回る）
例 ドミノ倒し ブランコ・PDCA・検証→改善
身近な例 消しゴムを使ったら減る（おしまい） テスト勉強のやり直し

見分け方のコツ（これがUnit 1の最重要ポイント）:

「結果」が「原因」に返ってきて、もう一度その原因を動かすかどうか。

返ってくる → ループ。返ってこない → 一直線。

5. 例で定着 — テスト勉強と部活（Interact）

例1: テスト勉強

  1. テストで悪い点を取った
  2. → 「勉強のやり方が悪かった」と気づく
  3. → やり方を変えて勉強する
  4. → 次のテストで点が上がる
  5. → 「このやり方が効く」と自信がつく
  6. → 3に戻る（さらに良いやり方を試す）

ここで「点が上がった（結果）」が「もっと勉強する（原因）」に返ってきています。これがループ。

例2: 部活の練習メニュー

  1. 大会で負けた
  2. → 「基礎が足りない」と気づく
  3. → 練習メニューを見直す
  4. → 次の大会で記録が伸びる
  5. → 伸びたことを確かめて、3に戻る（さらに改善）

これもループです。これを「改善のループ」と呼びます。

やってみよう: 上の例2の、どこで「結果が原因に返っている」かを指さしてみよう。

6. Check — 判定問題（これは一直線？ それとも丸い？）

それぞれ「一直線」か「丸い」か、理由つきで答えよう。

  1. リンゴが木から落ちた。（→ 落ちたらおしまい）
  2. 友達と仲良くすると笑顔が増える → さらに仲良くしたくなる。
  3. お菓子を食べたら無くなった。
  4. 走ると速くなる → 速いと楽しい → もっと走る。

答え合わせ（下を見る前に自分で答えよう）: 1. 一直線　2. 丸い　3. 一直線　4. 丸い

7. よくある誤解（Misconceptions）

誤解 正しい理解
「ループ＝同じことの繰り返し」 同じじゃなくて、結果が原因に返って、前より変わる。改善のループは、回るたびに少しずつ良くなる
「PDCAは仕事のやり方で、自分には関係ない」 テスト勉強・部活・趣味の練習、全部 PDCA と同じ構造

8. Teach-Back — 素人に説明しよう（ゴール）

次のテンプレで、「一直線と丸いの違い」を、システム思考を知らない人に説明してみよう。

  1. 何の話か: 「物事の見方には、一直線と丸いの2つがある」という話
  2. 部品は何か: 原因・結果・「結果が原因に返る」こと
  3. どう繋がるか: 原因→結果→また原因に返ると、ぐるぐる回る（ループ）
  4. 例: テスト勉強（点が上がる→自信→さらに勉強）
  5. よくある誤解: ループは同じ繰り返しじゃなく、回るたびに変わる
  6. 素人への一言: 「ドミノは倒したら終わり。ブランコはこげばまた返ってくる。物事をブランコみたいに見る考え方だよ」

9. まとめ（Takeaway）

  • 物事の見方は 一直線（原因→結果で終わる） と 丸い（結果が原因に返る） の2つがある
  • 結果が原因に返ることを「循環（ループ）」という
  • テスト勉強・部活・PDCA・検証→改善は、みんなループ
  • 次回は、この「ループ」の中身（何がたまり、何が流れるか）を詳しく見ていく

次回予告 (Unit 2): ループの中にある「たまるもの（ストック）」と「流れるもの（フロー）」を見つけよう。

Unit 2 — ストックとフロー：お風呂の水位で考える

対象: 中学2年生〜一般社会人 ゴール（基本編 L3 Teach-Back）: 「たまるもの（ストック）」と「流れるもの（フロー）」を区別し、変化のルールを人に説明できる 発展編 L5: ストックの変化を微分方程式 d(水位)/dt = 入り − 出 で記述できる 所要目安: 基本編 15〜20分 / 発展編 10〜15分

基本編（中2〜）

1. Hook — お風呂の水位

お風呂にお湯をためるときのことを思い出してください。

水位は、どうして上がったり下がったりするのでしょう？ 実は、たった1つのルールで説明できます。

2. なぜこれを学ぶのか？（Value）

世の中の「たまっているもの」は、ほとんど全部このルールで動いています。

  • お金（貯金がたまる）
  • 水（池・貯水タンク）
  • 人口（人がたまる）
  • 知識・体力・フォロワー数・在庫…

これが分かると、 「なぜ増えたり減ったりするのか」の理由が、絵を描くだけで分かるようになります。これがシステム思考の「見る力」の基本です。

3. ストックとフロー — 2つの仲間（Reveal）

まず、言葉の確認から。この2つは最初に区別するのが大事です。

名前 意味 お風呂の例 他の例
ストック（Stock） たまっているもの（その瞬間の量） 水位 貯金・在庫・人口
フロー（Flow） 流れているもの（増える/減る量） 蛇口の水・排水口の水 収入・支出・出生・死亡

Point: ストックは「今、どれだけあるか」、フローは「どれだけ流れているか」を教えてくれる。

4. 水位のルール（Interact）— これがUnit 2の最重要ポイント

お風呂の水位は、次の1本の式で表せます。

水位の変化 = 入ってくる水（蛇口） − 出ていく水（排水口）

このルールで、3つの場合を考えてみましょう。

場合 入りと出の関係 水位
A 入り > 出 上がる
B 入り < 出 下がる
C 入り = 出 変わらない

やってみよう: 上の図（蛇口と排水口）を紙に書いて、それぞれの場合に水位がどうなるかを描いてみよう。

ポイント: 「水位そのもの」ではなく「水位の変化」に注目しているところが大切。水位が高いか低いかではなく、入りと出のどちらが多いかで決まるのです。

5. 例で定着 — 貯金も同じ（Interact）

お風呂と同じルールで、貯金も説明できます。

お風呂 貯金
ストック 水位 貯金額
入り（フローIN） 蛇口の水 おこづかい・バイト代
出（フローOUT） 排水口の水 買い物・お小遣いの支出
ルール 入り − 出 入り − 出

「貯金が増える」＝ 入るお金 > 出るお金。 お風呂とまったく同じ構造です。これが「ストックとフロー」の考え方のすごいところ。構造が同じなら、別の分野でも同じ見方ができるのです。

6. Check — 確かめてみよう

それぞれ、ストックとフローを答えよう。

  1. コップの中の水 → ストック？ フロー？
  2. 蛇口から出る水 → ストック？ フロー？
  3. 今日の残金 → ストック？ フロー？
  4. 買い物で使うお金 → ストック？ フロー？

答え合わせ（下を見る前に自分で答えよう）: 1. ストック　2. フロー　3. ストック　4. フロー

おまけ問題: 「水位が下がっている」とき、蛇口と排水口はどちらが多い？

答え: 排水口（出）のほうが多い。

7. よくある誤解（Misconceptions）

誤解 正しい理解
「ストック＝増えるもの、フロー＝減るもの」 そんなことはない。ストックは「たまるもの」（増えも減りもする）。フローは「流れるもの」（入りと出の両方がある）
「水位が高い＝水位が上がっている」 水位の高さと水位の変化は別もの。高くても、出のほうが多いと下がる
「フローが大きい＝量が多い」 フローは「時間あたり」の流れ。1分にどれだけ流れるか

8. Teach-Back — 素人に説明しよう（基本編ゴール）

テンプレで「ストックとフロー」を、知らない人に説明してみよう。

  1. 何の話か: 物事には「たまるもの」と「流れるもの」がある、という話
  2. 部品は何か: ストック（たまるもの）・フローIN（入り）・フローOUT（出）
  3. どう繋がるか: 変化 = 入り − 出
  4. 図はどこを見ればいいか: 蛇口と排水口の両方がある絵
  5. よくある誤解: 水位の高さではなく、入りと出のどちらが多いかで変化が決まる
  6. 素人への一言: 「お風呂だよ。蛇口が排水口より多ければ水位は上がる。それだけ」

発展編（大学レベル・L4–L5）

必要な前提: math-bridge の B1〜B5（変化率と割合 → 関数とグラフ → 瞬間の変化率 → 微分の意味 → 微分方程式の第一歩） 中学2年生は発展編の前に B1〜B5 を先に読もう。数学が得意な人はスキップ可。各補助Unitは10〜15分。 math-bridge/README.md 参照。

9. Deepen — 「変化」を数式で書く

基本編のルールを、もう一度式で見てみましょう。

水位の変化 = 入り − 出

これは、数学の言葉ではこう書きます。

$$ \frac{d(\text{水位})}{dt} = \text{入り} - \text{出} $$
  • $d(\text{水位})$ … 水位のほんの少しの変化
  • $dt$ … ほんの少しの時間の変化
  • $\frac{d(\text{水位})}{dt}$ … 単位時間あたりの水位の変化（＝水位の増える速さ）

つまり「変化の速さ = 入り − 出」。基本編で言葉で言ったことと、完全に同じです。数式は、言葉のルールを短く正確にしたものという感覚を持てれば十分です。

式の読み方: 左辺 $\frac{d(\text{水位})}{dt}$ は「水位が増える速さ」。右辺 $\text{入り} - \text{出}$ は「蛇口から入る量から、排水口から出る量を引いたもの」。速さ＝入りマイナス出、という言葉のルールを省略記号で書いただけ。

記号の詳しい読み解きは math-bridge の B5（微分方程式の第一歩）で。

10. Deepen — ストックフロー図（記号で描く）

システムダイナミクスでは、この構造を「ストックフロー図」という正式な記号で描きます。

   [蛇口]  ──▶（入り）──▶ [□ 水位] ◀──（出）──◀ [排水口]
            フローIN         ストック    フローOUT
記号 意味
□（四角） ストック（たまるもの）
→ の矢印 フロー（流れるもの）
雲の形 ストックの外（入り・出の供給元・行き先）

この記号を使うと、貯金・人口・在庫が全部同じ図で描けるのが分かります。

詳しい作図手順（コンバータ・情報リンク含む）は Unit 2.5 で学びます。

11. Extend — 同じ構造を見つける（転移・L4）

ストックとフローは、社会のどこにでもあります。探してみよう。

  • スマホの充電: バッテリー残量（ストック）＝ 充電（入り）− 消費（出）
  • フォロワー数: フォロワー（ストック）＝ 増える（入り）− 減る（出）
  • 部活の練習: 技術（ストック）＝ 練習で身につく（入り）− さぼる・忘れる（出）

課題: 自分の身の回りから1つ見つけて、ストックとフローに分けてみよう。

12. Check-L5 — 発展編の確認

  1. $\frac{d(\text{水位})}{dt} = \text{入り} - \text{出}$ の式で、「入り < 出」のとき $\frac{d(\text{水位})}{dt}$ は正？ 負？ ゼロ？
  2. ストックフロー図の □ は何を表す？
  3. フォロワー数が「横ばい」のとき、入りと出の関係は？

答え: 1. 負（水位は下がる）　2. ストック（たまるもの）　3. 入り = 出

まとめ（Takeaway）

  • ストック = たまっているもの（水位・貯金・人口）
  • フロー = 流れているもの（入り・出）
  • 変化 = 入り − 出 が基本のルール。お風呂も貯金も人口も同じ構造
  • 数式では $\frac{d(\text{水位})}{dt} = \text{入り} - \text{出}$。言葉のルールを正確にしただけ（詳しくは math-bridge B5）
  • 次回は Unit 2.5 で、ストックフロー図（SFD）を自分で描く手順を学ぶ

Unit 2.5 — ストックフロー図（SFD）を作る：量の構造を1枚に落とす

対象: 中学2年生〜一般社会人（Unit 2 の直後） ゴール（L3 Teach-Back）: 身近な問題からストックフロー図（SFD）を自分で描き、ストック・フロー・コンバータ・情報リンクを説明できる 所要目安: 20〜25分 準備: Unit 2（ストックとフロー）を読んでいること

1. Hook — Unit 2 発展編の記号、覚えただけでは足りない

Unit 2 発展編では、お風呂の例を次の記号で紹介しました。

   [蛇口]  ──▶（入り）──▶ [□ 水位] ◀──（出）──◀ [排水口]

記号の意味は分かりました。でも、新しい問題に当たったとき：

  • 何をストックにするか迷う
  • フローが1本だけに見える（実は複数ある）
  • 「利率」「単価」のような中間の量をどこに書くか分からない

…となりがちです。

このUnitでは、ストックフロー図（SFD: Stock-and-Flow Diagram） を、問題の言葉から自分で描く手順を学びます。Unit 3.5 の因果ループ図（CLD）と対になる、SD の「量の地図」です。

ストックフロー図（SFD） 因果ループ図（CLD）
見るもの 何がたまり、何が流れるか 何が原因で何が変わるか
中心 ストック（□）とフロー 変数と因果矢印（＋／−）
向き 物質・量の移動 因果の向き
学ぶUnit このUnit（2.5） Unit 3.5

両方必要: CLD で「なぜそうなるか」の仮説を立て、SFD で「何がたまって何が流れるか」を固定する。Unit 9 の「構造を見る」では両方使います。

2. なぜこれを学ぶのか？（Value）

ストックとフローの概念（Unit 2）と、図として描く手順（このUnit）は別です。

  • 概念だけだと、頭の中で「たまる／流れる」と言えても、図に落とせない
  • 図に落とすと、抜けたフロー（見落とした支出・見落とした入り）が目に入る
  • チームで共有するとき、SFD は「みんなが同じ量の構造を見る」共通言語になる

3. SFD の部品（Reveal）

3.1 基本3部品（Unit 2 復習）

記号 名前 意味
□（四角） ストック その瞬間にたまっている量
パイプ上の矢印 フロー 単位時間あたりに増減する量
雲の形 源／行き先 ストックの外（宇宙・「どこから来るか不明」）

3.2 追加2部品（このUnitで新規）

記号 名前 意味
◇（丸角四角・小さな補助） コンバータ フローの「速さ」を決める中間量（利率・単価・割合など）
点線の矢印 情報リンク 「この量が、あのフローの速さを決める」という制御関係（物は流れない）

重要: 情報リンクは物やお金が流れる線ではない。「残高が多いほど利子が増える」のような影響の線です。

4. SFD を作る5ステップ（Interact）— このUnitの核心

Step1 ストックを1つ（まずは1つ）選ぶ — 何がたまる？
   ↓
Step2 フローIN・フローOUTを列挙 — 何が入って、何が出る？
   ↓
Step3 雲（源・行き先）を置く — 外から入る／外へ出る先
   ↓
Step4 コンバータと情報リンクを足す — フローの速さは何で決まる？
   ↓
Step5 検証する — 入り−出のルール・単位・読みやすさ

Step1 — ストックを選ぶ

「その瞬間の量」を1つ選ぶ。最初は1ストックで十分。

問題の言葉 ストック候補
貯金が増えない 貯金残高
お風呂の水位 浴槽の水量
在庫が足りない 倉庫の在庫数
フォロワーが伸びる フォロワー数

コツ: 「たまっている／たまりうるもの」はストック。フロー（収入・支出）と混ぜない。

Step2 — フローIN・フローOUTを列挙

ストックに対して：

  • フローIN（入り）: ストックを増やす流れ
  • フローOUT（出）: ストックを減らす流れ

貯金の例:

種類 フロー
IN 収入、利子
OUT 支出、手数料

Step3 — 雲を置く

フローの外側に雲（源・行き先）を置きます。

雲（給与）──▶ 収入 ──▶ [□ 貯金残高] ──▶ 支出 ──▶ 雲（生活費）

雲は「詳しく追わない世界」です。給与の内訳まで書かない、という割り切りもOK。

Step4 — コンバータと情報リンク

「フローの速さ」が他の量に依存するとき、コンバータと点線矢印を足します。

例: 利子

  • 利子（フローIN）の大きさは 利率 と 貯金残高 で決まる
  • 利率 → コンバータ（◇）に書く
  • 貯金残高（ストック）→ 利子（フロー）へ 情報リンク（点線）
  • 利率 → 利子 へも情報リンク
利率（◇）─ ─ ─▶ 利子（フローIN）
貯金残高（□）─ ─ ─▶ 利子（フローIN）

書き方のルール:

  • 実線の太い矢印 = 物・お金・量が流れる（フロー）
  • 点線の矢印 = 情報・影響が伝わる（情報リンク）
  • コンバータは「計算の中間」。ストックではない（たまらない）

Step5 — 検証する

# 問い 引っかかったら
1 ストックは「その瞬間の量」だけか？ フローをストックにしない
2 すべての入り・出を書いたか？ 抜けたフローを追加
3 情報リンクとフローを混同していないか？ 点線＝影響、実線＝流れ
4 基本ルール 変化 = 入り − 出 が言えるか？ 矢印の向きを見直す
5 単位が矛盾していないか？ 円/月・人・リットルなどを揃える

やってみよう: 紙に□を1つ描き、自分の貯金（またはお風呂）で Step1〜5 を実行。上の SVG と見比べる。

Unit 3 — フィードバックループ：増えると、どうなる？

対象: 中学2年生〜一般社会人 ゴール（基本編 L3 Teach-Back）: 「正のループ（強化）」と「負のループ（調整）」を見分け、結果が原因に返ることを自分の言葉で説明できる 発展編 L5: 正のループが指数成長になることを数理（e・倍々）で説明できる 所要目安: 基本編 15〜20分 / 発展編 10〜15分

基本編（中2〜）

1. Hook — YouTubeのフォロワー数

動画を投稿する人のフォロワー数を想像してください。

  1. 動画を投稿する → フォロワーが少し増える
  2. → フォロワーが多いと「人気だ」と見る人が増える
  3. → 再生回数が伸びる → おすすめに出やすくなる
  4. → さらにフォロワーが増える → 1に戻る

「増えた（結果）」が「さらに増やす（原因）」に返ってきています。これがフィードバックループです。

2. なぜこれを学ぶのか？（Value）

Unit 2 で「ストックとフロー」を学び、Unit 2.5 でストックフロー図（SFD）の作図手順を学んでいれば、「何がたまって何が流れるか」を図に固定できます。ここでは ストックの量がフロー自体を変える ことに注目します。

3. 2種類のループ（Reveal）

ループは2種類あります。最初に区別しておきましょう。

① 正のループ（強化ループ）—「増えると、もっと増える」

フォロワー（ストック）
   │
   ▼
見る人が増える ──▶ さらにフォロワーが増える ──▶ さらに見る人が増える…
  • 増えるとますます増える（減るとますます減る）
  • 雪だるま式・倍々ゲーム
  • 例: YouTubeフォロワー・うわさ・風邪の流行・貯金の利子

② 負のループ（調整ループ）—「増えると、止める方向に働く」

室温（ストック）
   │
   ▼
「暑い」と感じる ──▶ エアコンを下げる ──▶ 室温が下がる ──▶ 「ちょうどいい」
  • 増えると減らす方向に、減ると増やす方向に働く
  • バランスを取って「ちょうどいい」に落ち着く
  • 例: 室温調整・満腹・混雑回避

4. ループの図の書き方（Interact）

ループを図にするときの基本形：

       ┌───────────┐
       ▼           │
  [ストック]        │
       │           │
       ▼           │
  [フローを変える] ─┘
  • ＋（プラス）: 増えると増える方向
  • −（マイナス）: 増えると減らす方向
  • 輪（ループ）になっていることが大事

やってみよう: 上の「YouTubeフォロワー」と「室温」を、この形の図に書いてみよう。どちらが＋の輪で、どちらが−の輪か、印をつけよう。

5. 例で定着 — 正と負を見分ける（Interact）

場面 どんなループ？
風邪が流行る（うつす→増える→さらにうつす） 正（雪だるま）
満腹になる（食べる→お腹いっぱい→食べるのをやめる） 負（バランス）
貯金の利子（貯まる→利子がつく→さらに貯まる） 正
行列が混むと避ける（混む→避ける→空く） 負

見分け方のコツ:

「増えた結果、さらに増やす方向なら正。減らす（抑える）方向なら負。」

6. Check — 確かめてみよう

それぞれ正のループ？ 負のループ？

  1. ゲームで勝つ→自信がつく→さらに練習する→もっと勝つ
  2. お腹が空く→食べる→満腹→食べるのをやめる
  3. 夜更かしする→朝起きられない→夜更かしする（悪循環）

答え（下を見る前に自分で）: 1. 正　2. 負　3. 正（悪い雪だるま）　4. 負

誤解 正しい理解

9. Deepen — 正のループは「倍々」になる

正のループ（増えるともっと増える）を数式で見てみましょう。

ストックの増える速さが「今ある量に比例する」とき：

$$ \frac{d(\text{ストック})}{dt} = r \times \text{ストック} $$
  • $r$ … 増えやすさ（正の数）
  • 右辺に「ストック」自身が入っているのがポイント

これは「今の量に比例して増える」= 倍々ゲームです。これを解くと：

$$ \text{ストック}(t) = \text{ストック}(0) \times e^{r t} $$
  • $e$ … 約2.718…の特別な数（自然対数の底）
  • $e^{r t}$ … 時間とともに爆発的に大きくなる
  • これが指数成長

意味: 正のループをそのまま放っておくと、量は直線ではなくどんどん加速して増える（雪だるまが大きくなるほど転がるのが速くなる）。

10. Deepen — 負のループは「収束」する

負のループ（増えると抑える）では、量が目標値に近づくほど、増える速さが弱まります。

$$ \frac{d(\text{ストック})}{dt} = k \times (\text{目標} - \text{ストック}) $$
  • ストックが目標より小さい → 右辺が正（増える）
  • ストックが目標に近づく → 右辺が小さくなる（増え方が鈍る）
  • ストック = 目標 → 右辺 = 0（変化なし）

意味: 負のループは、量を目標になめらかに近づけて、そこに落ち着かせる。これが「ちょうどいい」に落ち着く理由の数理です。

11. Extend — 正と負の組み合わせ（転移・L4）

現実のシステムは、正と負が混ざっています。

  • 風邪の流行: 流行の初期は正のループ（拡大）→ 免疫ができる・対策する負のループ（抑制）が強まって、頭打ちになる
  • 人気商品: 売れて人気が出る正のループ → 在庫切れ・飽きられる負のループで落ち着く

課題: 「成長するけど、どこかで頭打ちになる」ものを1つ見つけて、正と負のループを1つずつ指摘してみよう。

  1. 正のループ（倍々）のグラフの形は？
  2. 負のループは最終的にどこに落ち着く？
  3. $r > 0$ のとき、$e^{r t}$ は時間とともにどうなる？

答え: 1. 加速する曲線（指数成長）　2. 目標値　3. 爆発的に大きくなる

まとめ（Takeaway）

  • 正のループ（＋）: 増えるともっと増える。雪だるま式。放っておくと指数成長
  • 負のループ（−）: 増えると抑える。バランスを取って目標に落ち着く

Unit 3.5 — 因果ループ図（CLD）を作る：構造を「1枚の図」に落とす

対象: 中学2年生〜一般社会人（Unit 3 の直後） ゴール（L3 Teach-Back）: 身近な問題から因果ループ図（CLD）を自分で描き、正/負のループを見分けて人に説明できる 所要目安: 20〜25分 準備: Unit 3（正/負のループ）を読んでいること

1. Hook — Unit 3 の図と、今から作る図は違う

Unit 3 では、ループを次のような形で描きました。

       ┌───────────┐
       ▼           │
  [ストック]        │
       │           │
       ▼           │
  [フローを変える] ─┘

これは「ぐるぐる回る関係」を掴むための入門用の図です。十分役に立ちます。

でも、実務や教科書でいうシステムダイナミクスの 因果ループ図（CLD: Causal Loop Diagram） は、もう少し決まった書き方があります。

Unit 3 の簡易ループ図 因果ループ図（CLD）
ノード ストック中心 変数（状態・量・率など）
矢印 流れの方向 因果（Aが増えるとBはどう変わる？）
印 ＋／−（概念） 矢印ごとに ＋／− の極性
ループ名 正/負 R（強化）／B（調整） と番号

このUnitでは、問題の言葉から CLD を1枚描く手順を学びます。Unit 9（SDの切り口）や演習で「構造を見る」ときの土台になります。

2. なぜこれを学ぶのか？（Value）

Unit 3 で「正/負のループ」は分かりました。でも、新しい問題に当たったとき：

  • 何をノードに書くか迷う
  • 矢印の向きがブレる
  • ＋と−の付け方が不安

…となりがちです。CLD は「構造の仮説を1枚に固定する」道具です。頭の中だけだと見落としが残りますが、紙やタブレットに描くと、抜けた因果・おかしな矢印が目に入ります。

CRT（Unit 7）との違い: CRT は TOC の「根本原因を1本に絞る木」。CLD は SD の「循環する因果の地図」。両方とも矢印図だが、目的が違う。 CLD はループの極性（R/B）を見る。CRT は Root への収束を見る。

3. CLD の部品（Reveal）

3.1 変数（ノード）

変化する・変化しうるものを、短い名詞で書きます。

書ける例 避けたい例
夜更かしの時間 「生活が乱れる」（抽象・広すぎ）
睡眠不足 「ストレス」（中身が人によって違う）
翌朝の眠気 「だから疲れる」（因果の言葉が混ざる）

コツ: 「今、増えたり減ったりしているもの」「これが変わると他が変わるもの」を列挙する。

3.2 因果矢印と極性（＋／−）

矢印は 原因 → 結果 の向き（左の変数が増えると、右はどうなる？）。

極性 意味 例
＋ 左が増えると、右も同じ方向に変わる 夜更かし↑ → 睡眠不足↑
− 左が増えると、右は反対方向に変わる 睡眠不足↑ → 翌朝の元気↓

極性の付け方（最重要ルール）:

矢印の左側の変数が少し増えたら、矢印の右側は増える（＋）か減る（−）か？

「増えたから増える」なら＋。「増えたのに減る」なら−。

3.3 ループの極性（R / B）

輪になったら、ループ全体の性質を決めます。

記号 名前 中身 Unit 3 との対応
R Reinforcing（強化） ループ内の−の数が 偶数（0, 2, 4…） 正のループ
B Balancing（調整） ループ内の−の数が 奇数（1, 3, 5…） 負のループ

数え方: ループを1周するとき、通る矢印の−を数える。偶数なら R、奇数なら B。

4. CLD を作る6ステップ（Interact）— このUnitの核心

新しい問題に当たったら、次の順で進めます。

Step1 問題の言葉を書き出す（観測・不満・変化）
   ↓
Step2 変数に直す（短い名詞。因果の言葉はまだ混ぜない）
   ↓
Step3 因果矢印を引く（原因 → 結果。「A↑ならBは？」）
   ↓
Step4 各矢印に＋／− を付ける
   ↓
Step5 ループを見つけて R / B を判定する
   ↓
Step6 検証する（下のチェック表。Unit 7 §4.5 と同型）

Step1 — 問題の言葉を書き出す

「観測できること」「困っていること」を箇条書き。解決策は書かない。

例（朝起きられない）: - 朝、起きられない - 夜更かしする - 授業中に眠い - 夜、スマホを見る

Step2 — 変数に直す

問題の言葉 変数（ノード候補）
夜更かしする 夜更かしの時間
授業中に眠い 昼の眠気
朝、起きられない 翌朝の起床のしやすさ（※「しやすさ」は主観でも変数にできる）
夜、スマホを見る 寝る前のスマホ使用

3〜6個に絞る。最初は多くてもよいが、図は読みやすく。

Step3 — 因果矢印を引く

「Aが増えると、Bはどう変わる？」で A → B。

夜更かしの時間 ──→ 睡眠不足
睡眠不足 ──→ 昼の眠気
昼の眠気 ──→ 夜の活動への意欲（昼に消耗→夜に元気）
夜の活動への意欲 ──→ 夜更かしの時間
寝る前のスマホ使用 ──→ 夜更かしの時間

矢印は1本ずつ理由を言えるものだけ。迷ったら一旦書いて Step6 で検証。

Step4 — 極性を付ける

矢印 左↑のとき右は？ 極性
夜更かし → 睡眠不足 睡眠不足も↑ ＋
睡眠不足 → 昼の眠気 昼の眠気も↑ ＋
昼の眠気 → 夜の活動への意欲 意欲も↑（夜に活動したくなる） ＋
夜の活動への意欲 → 夜更かし 夜更かしも↑ ＋
スマホ使用 → 夜更かし 夜更かしも↑ ＋

Step5 — ループを見つける

上の4変数（夜更かし→睡眠不足→昼の眠気→夜の活動意欲→夜更かし）が R1（強化ループ）。矢印はすべて＋ → −は0個 → 偶数 → R。

悪循環（雪だるま）の典型です。Unit 3 の「正のループ」と同じ構造を、CLD 記法で固定した形です。

Step6 — 検証する

Unit 7 §4.5 の因果検証と同じ精神です。CLD 用に短くまとめたチェック：

# 問い 引っかかったら
1 変数は短い名詞で、観測・想像できるか？ 抽象語を分解
2 矢印は「原因→結果」で、逆になっていないか？ 向きを直す
3 ＋／−は「左↑なら右は？」で付けたか？ 極性を見直す
4 ループの R/B は−の個数で合っているか？ 再カウント
5 「後で起きた＝原因」になっていないか？ Unit 7 §4.5 を参照

やってみよう: 紙に変数を書き、矢印と＋／−を入れてから R/B を付ける。完成図は上の SVG と見比べる。

Unit 4 — 時間の遅れ：効き目は後から出る

対象: 中学2年生〜一般社会人 ゴール（基本編 L3 Teach-Back）: 「時間の遅れ」が何か、なぜ「やりすぎ」を起こすかを自分の言葉で説明できる 発展編 L5: 遅れをモデルに組み込むと、システムが行き過ぎや揺れを起こすことを数理で説明できる 所要目安: 基本編 15〜20分 / 発展編 10〜15分

基本編（中2〜）

1. Hook — 料理の味付け

カレーやスープの味付けをしている場面を想像してください。

  1. 味見をしたら「ちょっと薄い」
  2. → 塩を足す
  3. → 味見する → まだ薄い（味がしみこむまで時間がかかる）
  4. → また塩を足す
  5. → あとから味が全体に回って、一気にしょっぱくなる ← やりすぎ

「効き目が後から出る」ために、ついやりすぎてしまう。これが時間の遅れです。

2. なぜこれを学ぶのか？（Value）

Unit 3 で「結果が原因に返る（フィードバック）」を学びました。Unit 3.5 で因果ループ図（CLD）の作図手順を学んでいれば、「構造を図に固定する」準備はできています。ここでは 効き目がすぐに返ってこない ことに注目します。原因を変えても、効果が現れるまで時間がかかる。これが「時間の遅れ」です。

遅れを知らないと、「効果がない」と勘違いしてやりすぎる・あきらめる、という失敗をします。遅れを知っていると、待つことができる。これは実生活で役立つ大事な考え方です。

3. 時間の遅れとは（Reveal）

時間の遅れ = 原因から結果が現れるまでの「空白の時間」

遅れの種類：

種類 意味 例
知覚の遅れ 変化に気づくまで時間がかかる 味に気づくのが遅れる・水温に気づくのが遅れる
反応の遅れ 行動しても効くまで時間がかかる 塩がしみこむ・薬が効く・肥料が効く
伝達の遅れ 情報が届くまで時間がかかる 注文して届くまで・返事が来るまで

4. 遅れがあると「やりすぎ」になる（Interact）— 最重要ポイント

遅れがあると、こんな悪循環が起きます。

1. 薄い → 塩を足す
2. まだ薄い（効く前） → また足す
3. 遅れて全部効く → しょっぱすぎる ← やりすぎ
4. しょっぱい → 水を足す（薄める）
5. まだしょっぱい（効く前） → また水を足す
6. 遅れて全部効く → 味が薄くなる ← またやりすぎ

これを図にすると、行ったり来たりの揺れ（ジグザグ）になります。

やってみよう: このジグザグを描いて、「やりすぎ→直す→やりすぎ」が繰り返されることを確かめよう。

5. 例で定着 — 他にもある遅れ（Interact）

場面 遅れの内容
部屋の温度 エアコンを上げても、すぐには暖まらない
宿題の効果 勉強しても、成績に現れるまで時間がかかる
肥料 まいても、すぐには育たない
薬 飲んでも、効くまで時間がかかる

「効き目は後から出る」 ことを知っているだけで、急いでやりすぎるのを防げます。

6. Check — 確かめてみよう

  1. 時間の遅れとは何？（一言）
  2. 塩を足して「まだ薄い」とき、正しい行動は？
  3. 遅れがあると、なぜやりすぎが起きる？

答え（下を見る前に自分で）: 1. 原因から結果までの空白の時間　2. 待ってから味見する　3. 効く前に「効果がない」と判断して足してしまうから

7. よくある誤解（Misconceptions）

誤解 正しい理解
「効果がない＝やり方が間違い」 効果が出るまで時間がかかっているだけかもしれない。遅れを考慮して「待つ」ことが大事
「時間の遅れはただの待ち時間」 待ち時間以上の意味がある。やりすぎ・揺れ・判断ミスを生む原因になる

8. Teach-Back — 素人に説明しよう（基本編ゴール）

テンプレで「時間の遅れ」を説明しよう。

  1. 何の話か: 「効き目が後から出る」ことが失敗を生む、という話
  2. 部品は何か: 原因・遅れ・結果・やりすぎ
  3. どう繋がるか: 原因→（遅れ）→結果。結果が出る前に判断するとやりすぎる
  4. 図はどこを見ればいいか: 原因と結果の間にある「空白」
  5. よくある誤解: 効果がない＝間違い、ではない
  6. 素人への一言: 「カレーだよ。塩を足してすぐ味見しても、まだ薄い。しばらく待たないと、実はしょっぱくなってる」

発展編（大学レベル・L4–L5）

必要な前提: math-bridge の B1〜B6（特に B5 微分方程式・B6 指数成長）。中2は先に読もう。

9. Deepen — 遅れを数式で表す

時間の遅れをモデルに組み込むと、システムの動きが変わります。

遅れのない負のループ（室温調整）では、すぐに目標に近づきます。

$$ \frac{d(\text{温度})}{dt} = k \times (\text{設定温度} - \text{温度}) $$

ここに「実際に効く温度変化は、操作から遅れてやってくる」という遅れを入れると、式は複雑になり、動きは「行き過ぎ→戻す→行き過ぎ」の振動になります。

直感的な説明: エアコンを上げても、室温が上がるまで時間がかかる。その間に「まだ寒い」とさらに上げてしまう。遅れて一気に暖かくなって、今度は暑すぎる。これが繰り返されて、温度は設定値の周りを揺れます。

10. Deepen — 行き過ぎ（オーバーシュート）の原因

遅れが大きいほど、行き過ぎも大きくなります。

遅れ システムの動き
遅れなし なめらかに目標へ（Unit 3 で学んだ収束）
遅れあり（小） 少し揺れながら目標へ
遅れあり（大） 大きく行き過ぎて、激しく揺れる（場合によっては発散）

遅れ = 揺れの源。 これを知っていると、なぜ「急に反応しすぎると悪化する」のかが分かります。

11. Extend — 遅れを「待つ」ことの価値（転移・L4）

  • 経営判断・政策・教育・ダイエット・筋肉トレーニング… すべて「効き目に遅れがある」
  • 「すぐ結果を求める」と、遅れがあるシステムではやりすぎを起こす
  • 遅れを知っている = 待てる = 正しく判断できる

課題: 自分が「効果が遅い」と思っているもの（勉強・運動・趣味の練習）で、今日から「待つ」を意識してみよう。

12. Check-L5 — 発展編の確認

  1. 遅れがあると、負のループの動きはどう変わる？
  2. 遅れが大きいほど、行き過ぎはどうなる？
  3. 「やりすぎ」の対策として、遅れの観点から言えることは？

答え: 1. 揺れ（振動）が起きる　2. 大きくなる　3. 効果が出るまで待つ（判断を急がない）

まとめ（Takeaway）

  • 時間の遅れ = 原因から結果までの空白の時間
  • 遅れがあると「効果がない」と誤解してやりすぎが起きる
  • 遅れはシステムに揺れ・行き過ぎをもたらす
  • 対策の基本は「待つ」
  • これで SD の基本3要素（ストック・フロー・フィードバック・遅れ）がそろった

Unit 5 — ボトルネック：一番遅いところが全体を決める

対象: 中学2年生〜一般社会人 ゴール（基本編 L3 Teach-Back）: 「一番遅いところ（ボトルネック）が全体の速さを決める」ことを説明でき、例で示せる 発展編 L5: 待ち行列（キュー）の基礎で、ボトルネックに「たまる」ことを数理で説明できる 所要目安: 基本編 15〜20分 / 発展編 10〜15分

基本編（中2〜）

1. Hook — 運動会のリレー

運動会のリレーを思い出してください。チームの速さを決めているのは、だれでしょう？

  • 一番速い人？ → いいえ
  • 平均的な走者？ → いいえ

答え: 一番遅い人。 バトンが一番遅い人に届くと、そこでチーム全体が待たされるからです。

一番遅い走者を速くすれば、チーム全体が速くなります。でも、一番速い走者をさらに速くしても、全体はあまり変わりません（次の遅い人が待たされるだけ）。

これがこのUnitのすべて。「一番遅いところが、全体を決める」

2. なぜこれを学ぶのか？（Value）

Unit 1〜4 で「構造を見る力（SD）」を学びました。では、見えた構造の中でどこに手を打つべきか？ これがTOC（制約理論）の出番です。

TOC の答えは一言です。

「一番遅いところ（ボトルネック＝制約）を直せば、全体が速くなる。」 逆に、それ以外をいくら頑張っても、全体は速くならない。

これを知っていると、「どこを直すか」が迷わず決まります。全体を平均的に頑張るより、一番遅い1箇所に集中するほうが圧倒的に効率的です。

3. ボトルネックとは（Reveal）

ボトルネック = システム全体の速さを決めている、一番遅い（能力が小さい）部分

名前の由来は「瓶の首」。瓶から液体を注ぐとき、速さを決めるのは瓶の口の太さです。胴体がどんなに太くても、首が細ければそこに詰まる。

【瓶】
 ┌─────────────┐
 │  どんなに太くても      │
 │  ここの太さは関係ない    │
 └──────┬──────┘
         ▼
        ─────   ← 瓶の首（ボトルネック）
                 ここが細いと、全体の速さがここで決まる

4. 工場の例（Interact）— 一番分かりやすい図解

複数の工程が流れて、最後に1つの製品になる工場を想像してください。

工程1・2・3 がいくら速くても、工程4（組み立て）が遅いと、製品はそこに並んで待つだけです。

  • 工程4 が「1時間に10個」しか作れない
  • 工程1・2・3 が「1時間に20個」作っても、完成品は1時間に10個
  • 余った10個分は、組み立ての前にたまっていく（在庫になる）

つまり: 全体の生産速度は、工程4（ボトルネック）の速度そのもの。工程1〜3を頑張っても、完成品は増えません。

やってみよう: 上の図で、ボトルネック（全体の速さを決めているところ）を指さしてみよう。また、どこを直せば全体が速くなるか、丸をつけよう。

5. 例で定着 — 身近なボトルネック（Interact）

場面 ボトルネック（一番遅いところ）
運動会のリレー 一番遅い走者
お店のレジ 列をさばくレジ（待たせているところ）
給食の配膳 一番時間のかかる作業（ご飯を盛る？ おかずを分ける？）
宿題 一番苦手な科目（ここに時間がかかる）
工場 一番生産が遅い工程（上記の例）

共通点: 「一番遅いところ」にモノや人がたまる。だから、どこがボトルネックかは「どこに行列ができているか」を見れば分かります。

6. Check — 確かめてみよう

  1. チームの速さを決めるのは、リレーのどの走者？
  2. 工場で、完成品の数が「1時間に10個」で頭打ちなのは、どこが原因？
  3. ボトルネックを見つける手がかりは？（ヒント: どこに何がたまる？）

答え（下を見る前に自分で）: 1. 一番遅い走者　2. 一番生産が遅い工程（組み立て）　3. モノや人がたまっている（行列ができている）ところ

7. よくある誤解（Misconceptions）

誤解 正しい理解
「みんなで頑張れば全体が速くなる」 ボトルネック以外を頑張っても、全体は速くならない。頑張りはボトルネックに集中すべき
「一番大切な工程を直せばいい」 「大切」ではなく「一番遅い」が基準。速くても重要でも、ボトルネックでなければ全体は変わらない
「ボトルネック＝ボトルネック以外の人が暇でいい」 待ちが生まれるのは仕組みの問題。直すべきはボトルネックの能力で、他の工程が暇になるのは別の問題

9. Deepen — ボトルネックに「たまる」を数理で見る

工場の例を、Unit 2 で学んだストックフローで考えると、ボトルネックの前には「在庫（ストック）」ができます。

入ってくる個数(フローIN) ──▶ [ボトルネック前の在庫] ◀── 出ていく個数(フローOUT)
                                ↑ここにたまる

ボトルネックの処理能力（出）より入ってくる量（入り）が多ければ、在庫が増えます。

$$ \frac{d(\text{在庫})}{dt} = \text{入ってくる個数} - \text{処理できる個数} $$
  • 入り > 処理 → 在庫が増える（行列が伸びる）
  • 入り = 処理 → 在庫は一定（行列は変わらない）
  • 入り < 処理 → 在庫が減る（行列が短くなる）

全体の生産量 = ボトルネックの処理能力。 入ってくる量がどれだけ多くても、出ていく量（完成品）はボトルネックの能力で頭打ちになります。これが「制約が全体を決める」の数理です。

10. Deepen — 待ち行列（キュー）の基礎

ボトルネックに「たまる」ことを学ぶのが待ち行列理論です。

要素 意味
到着率 $\lambda$ 1時間に何個（何人）来るか
サービス率 $\mu$ 1時間に何個（何人）処理できるか
  • $\lambda < \mu$ … 処理が追いつく。待ちは伸びない
  • $\lambda > \mu$ … 処理が追いつかない。待ち行列が伸び続ける
  • $\lambda = \mu$ … ぎりぎり。ほんの少し乱れると行列が伸び始める

直感: レジの処理速度（$\mu$）よりお客さんが来る速さ（$\lambda$）が速いと、行列は際限なく伸びる。処理を速くするか、客の到着を減らすしかない。

  2. 活用する: ボトルネックの能力を最大限使う（アイドル時間を減らす）
  3. 従属させる: それ以外の工程は、ボトルネックに合わせて動く（作りすぎない）
  4. 強化する: ボトルネックの能力そのものを上げる
  5. 繰り返す: 直すと次のボトルネックが現れる（→ Unit 6）

課題: 自分の生活（勉強・部活・家事）で「ボトルネック」を1つ見つけ、どう直すか考えてみよう。

Unit 6 — 5つの集中ステップ：制約をどう直すか

対象: 中学2年生〜一般社会人 ゴール（基本編 L3 Teach-Back）: 改善の5ステップを、Unit 5 の例（リレー・工場）に当てはめて説明できる 発展編 L5: TOC の思考プロセス（CRT・蒸発する雲）への橋渡しを理解できる 所要目安: 基本編 15〜20分 / 発展編 10〜15分

基本編（中2〜）

1. Hook — 前回の続きから

Unit 5 で「ボトルネック（一番遅いところ）が全体を決める」と学びました。

  • リレーでは一番遅い走者
  • 工場では一番生産が遅い工程

では、そのボトルネックをどう直すか。ここからが今回の話です。同じ事例（リレー・工場）を最後まで使って、「直す手順」を学びます。

2. なぜこれを学ぶのか？（Value）

「どこを直すか」が分かっても、どう直すかが分からなければ改善は進みません。TOC は、改善の正しい順序を5つのステップにしました。

これを知ると、以下のような失敗を防げます。

「全部の工程をまんべんなく頑張ったのに、全体は変わらなかった」

「順番」が大事です。制約を直す→次を探すの繰り返しで、改善はどんどん進みます。

3. 5つの集中ステップ（Reveal）

TOC の生みの親・ゴールドラットが提唱した改善の基本手順です。

ステップ 名前 内容
1 見つける 制約（ボトルネック）はどこか
2 活用する 制約を最大限に使う（無駄な待ちを減らす）
3 従属させる 他の工程を制約に合わせて動かす
4 強化する 制約の能力そのものを上げる
5 繰り返す 制約が動いたら、次の制約を探す

4. 工場の例で追う（Interact）— 5ステップを最後まで

Unit 5 の工場を思い出してください。

[工程1: 切る] → [工程2: 磨く] → [工程3: 塗る] → [工程4: 組み立て] → 完成品

工程4（組み立て）が「1時間に10個」しか作れず、全体がここで頭打ちになっているとします。

ステップ1: 見つける

制約はどこか？ → 工程4（組み立て）。ここに在庫がたまっている（Unit 5 で確認済み）。

ステップ2: 活用する

「今ある工程4の能力を、無駄なく使う」ことを考えます。

  • 工程4の機械が、休憩中や段取り替えで止まっていないか
  • 工程4の人が、別の作業をさせられていないか

→ 能力を上げなくても、使っていない時間を無くすだけで生産が増えることがあります。ここが最初。

ステップ3: 従属させる

「他の工程は、工程4に合わせて動かす」ことを考えます。

  • 工程1〜3が作りすぎると、工程4の前に在庫がたまるだけ
  • 工程1〜3は、工程4が処理できる量だけ作る

→ 作りすぎをやめる。工程1〜3の頑張りを「制約に合わせて」調整します。

ステップ4: 強化する

ここで初めて「工程4の能力そのものを上げる」ことを考えます。

  • 機械を新しいものにする
  • 人員を増やす
  • 作業を工夫して速くする

→ 1・2・3の順で考えるからこそ、無駄な投資（必要ない強化）を避けられます。ステップ2で空き時間を無くせば、機械を買わずに済むかもしれません。

ステップ5: 繰り返す

工程4が速くなると、次に遅い工程がボトルネックになります（例: 工程2の磨き）。

→ 1に戻って、新しい制約を直す。これを繰り返すと、全体がどんどん速くなります。

やってみよう: 工場の例で、5ステップを順番に追ってみよう。なぜ「強化（ステップ4）」が最後なのか、考えてみよう。

5. リレーの例で確かめる（Interact）

Unit 5 のリレーでも、同じ5ステップが使えます。

ステップ リレーでの意味
1 見つける 一番遅い走者を特定する
2 活用する その走者の走り方・スタートの仕方を工夫する（能力は変えずに）
3 従属させる 他の走者は、一番遅い走者に合わせて待つ（無理に飛ばさない）
4 強化する その走者を鍛える・走順を入れ替える
5 繰り返す 速くなったら、次の遅い走者を直す

順序が大事な理由: ステップ2（工夫）で十分なら、ステップ4（強化＝時間とお金）は不要。安い・早い順にやるのが5ステップの考え方です。

6. Check — 確かめてみよう

  1. 5ステップの順番を言える？
  2. なぜ「強化する（ステップ4）」は最後なのか？
  3. ステップ5（繰り返す）で何が起きる？

答え（下を見る前に自分で）: 1. 見つける→活用→従属→強化→繰り返す　2. 工夫や調整で足りるなら、お金のかかる強化は不要だから　3. 次のボトルネックが現れるので、1に戻る

誤解 正しい理解
「改善＝いきなり新しい設備・投資」 まず活用（2）と従属（3）を試す。強化（4）は最後
「一度直せば終わり」 制約は移動する。繰り返し（5）が改善の本質
「5ステップは工場だけの話」 リレー・勉強・部活など、どこでも使える手順

9. Deepen — 5ステップは「どこに手を打つか」の思考法

  • ステップ2（活用）: 到着率 $\lambda$ とサービス率 $\mu$ の差を、無駄なく詰める
  • ステップ4（強化）: $\mu$ そのものを上げる（$\mu > \lambda$ にする）
$$\mu < \lambda \text{ の間は、待ち行列は伸び続ける（発散）}$$

つまり「$\mu$（処理能力）が $\lambda$（到着）より小さければ、何をしても全体は詰まる」— これが制約の数理的な正体です。

09Unit 7unit7_crt.md

Unit 7 — 演習A（基本編）: CRTを作る — 現状問題ツリーで「本当の原因」を見つける

対象: 中学2年生〜一般社会人 ゴール（L3 Teach-Back）: 「個別対策では解決しない理由」と「根本原因（Root）に集中すると効率的に解決できる」ことを、自分の言葉で説明できる。CRTで根本原因を1つ特定できる 所要目安: 20〜30分（例題つき） 準備: 演習カード exercises/ex1_getting_up.md（例題）を手元に

1. Hook — まず「朝起きられない」を直してみよう（体験）

Aさんは朝起きられずに困っています。原因は「よく分からない」まま、いろいろ試してみました。

試した対策 結果
「朝ごはんを食べるようにした」 変わらない（そもそも食べる時間がない）
「授業を楽しくしようと頑張った」 眠くなるのは変わらない
「スマホをやめようとした」 1日は我慢できるけど、また戻る
「疲れを取ろうと早く寝ようとした」 なぜか夜更かししてしまう

全部、それっぽいのに、ぜんぜん解決しません。

ここが大事な体験です。 原因が分からないまま対策を打つと、症状を1個ずつ追いかける「モグラ叩き」になり、どれも根本からは直りません。

2. なぜ個別対策では解決しないのか（Value）

症状は「枝」で、原因は「根」にある

木を想像してください。枯れているのは葉っぱ（症状）ですが、問題の本当の場所は根（根本原因）にあります。

    葉っぱ（症状）: 朝起きられない・眠い・朝ごはんを食べられない・疲れてる…
       │
       │ （葉っぱを1枚ずつ直しても、根がダメならまた枯れる）
       ▼
     根（根本原因）: 夜更かし  ← ここを直すと、葉っぱがまとめて元気になる
  • 個別対策 = 葉っぱを1枚ずつ治そうとする（モグラ叩き・非効率）
  • 根本対策 = 根を1本直す（葉っぱがまとめて良くなる・効率的）

この「根を見つけて、そこに集中する」ことが、合理的で効率的な解決の第一歩です。

CRTの意義（このUnitの核心）

「原因が分かりにくい状態」から、因果関係でつなぎ合わせることで「根（Root）」を1つに絞り込む。それがCRT（現状問題ツリー）を作る意義です。

  • CRTを作る前: 原因がいくつもあるように見えて、何を直せばいいか分からない
  • CRTを作った後: Root（根本原因）が1つに見える。直す場所が決まる

3. CRTとは（Purpose→Meaning）

Purpose（目的）

問題（UDE）を因果関係でつないだ「木のような図」を作り、Root（根本原因）を1つに絞り込む。

Meaning（意味）

用語 意味
UDE（Undesirable Effect） 現状の不都合な事象（症状・観測できる問題）
Cause（原因ノード） UDEの背後にある原因。観測できる症状ではないが、「なぜUDEが起きるか」を説明するノード
CRT（Current Reality Tree） 現状問題ツリー。UDEとCauseを「なぜなら」でつないだ図
Core Constraint / Root 根本原因。矢印が一番多く「原因」として出ているノード

CRTには2種類のノードがある

CRTは、UDE（症状）と Cause（原因）の2種類のノードでできています。

[UDE] 観測できる症状（朝起きられない・眠い・疲れてる）
  ↑ 「なぜなら」
[Cause] その原因（睡眠不足・夜更かし・スマホ）← 症状ではないが、原因としてある
  ↑ 「なぜなら」
[Root] 根本原因（夜更かし）← 矢印が一番出ている
  • Step1では「観測できる症状」から始める（起点はUDE）
  • Step2で原因を掘り下げると、UDEではない Cause が次々と現れる（スマホ・睡眠不足・習慣など）
  • 掘り下げの果てに Root（根本原因） へ到達する

大切なこと: CRTは「症状（UDE）だけの図」ではありません。症状から出発して、原因（Cause）を掘り下げ、Rootに至るまでの全体図です。Step1で「原因は書かない」と言うのは、最初の出発点を症状に揃えるためであって、原因ノードを書いてはいけない、という意味ではありません。

4. CRTの作り方（5ステップ）

Step1 問題（UDE）を列挙する
   ↓ 出発点。「観測できる症状」を1項目1文で書き出す
Step2 因果でつなぐ・原因を掘り下げる
   ↓ 「Aが起きる、なぜならBだから」の矢印で結ぶ
   ↓ 症状の背後にある Cause（原因ノード）も追加していく
Step3 因果を検証する（思い込みをチェック）
   ↓ 引いた矢印は本当に因果か？ 相関・逆・別原因・飛躍をチェック（下のチェック項目）
Step4 輪（ループ）を探す
   ↓ 悪循環（負のループ）があれば、それが「現状が続く理由」
Step5 Root（根本原因）を特定する
   ↓ 「原因」として矢印が一番多く出ているノードが Core Constraint

補足: ノードのラベル（UDE / Cause / Root）は、CRTの中で相対的です。あるノードは、上から見れば「原因（Cause）」、下のノードから見れば「結果」です。ラベル分けは、どこが観測できる症状（UDE）で、どこが内部の原因（Cause）かを区別するための目印として使います。

4.5. 因果の検証チェック — その矢印、本当に因果？

これは一般の人も間違えやすい最重要ポイント。 私たちは「前後で起きたこと」を見ると「原因だ」と思い込みがちです。

「Aの後にBが起きた」だけでは、因果とは言えません。矢印を引く前に、次のチェックで検証しましょう。これはTOCの CLS 8原則（因果の正しさを確かめる8つのメガネ）を平易にしたものです。

# チェック項目 問い 例（おかしな矢印）
1 意味が明確か 言葉の意味は誰にでも通じるか？ 抽象語ではないか 「ストレス」→「体調不良」（ストレスとは何？）
2 存在するか AもBも、現実に確かめられる事実か？ 「おまじないをした」→「テストで良い点を取った」
3 本当にAが原因か Aを取り除いたら、Bは起きなくなるか？（だからテスト） 「朝ごはんを食べない」→「眠くなる」…実は睡眠不足が原因では？
4 Aだけで十分か 他に必要な原因Cはないか？ 「スマホを見た」→「夜更かし」（寝る時間という条件も必要）
5 別の原因Dではないか 本当は別の要因のせいではないか？ 「アイスの売上が上がった」→「水難事故が増えた」（どちらも「夏」が原因）
6 逆ではないか 実はBが原因でAが結果では？ 「成績が良い→スマホを触らない」（逆に「スマホを見ない→成績が良い」？）
7 別の結果も予言できるか A→Bが本当なら、別のEも同時に見えるはずではないか？ 「夜更かし→朝起きられない」なら、「休日も遅くまで寝る」はず
8 飛躍していないか AとBの間に、抜けた中間Xはないか？ 「イライラする」→「友達と衝突」（間に「感情をうまく伝えられない」がある）

特に一般の人がよくやる間違い（トップ3）

  1. 「後で起きた＝原因」思い込み（前後関係と因果の混同） - 例: 「アイスを食べた翌日に風邪を引いた → アイスのせい？」（本当は別）
  2. 逆因果の見落とし - 例: 「よく笑う人は健康だ → 笑うから健康？」（健康だから笑える、の可能性も）
  3. 第3の原因の見落とし（見かけの相関） - 例: 「都会ほど犯罪が多い → 都会が犯罪を生む？」（実は「人が多い」だけ）

5. 例題（EX1: 朝起きられない）— Rootが見える体験をしよう

「原因が分からない」状態から、CRTを作って Root を1つに絞る体験を追います。

Step1: 出発点は、観測できる症状（UDE）から

CRTは「観測できる症状」から始める。原因はまだ探さない。まずはっきり見えている症状だけを書く。

ここがポイント。Aさんの問題は「朝起きられない」だけではありません。一見バラバラに見える複数の症状があります。

# UDE（観測できる症状）
UDE1 朝、起きられない
UDE2 朝ごはんを食べない
UDE3 授業中に眠くなる
UDE4 成績が下がった
UDE5 イライラして友達と衝突する

「朝起きられない」「成績が下がる」「友達と衝突する」…全部別々の問題に見えます。これを1本のツリーにしていきます。

Step2: 「なぜなら」でつなぎ、原因（Cause）を掘り下げる

「Aが起きるのは、なぜならBだから」の矢印で、それぞれの症状の原因を掘り下げていく。

[UDE: 朝、起きられない]
   │ なぜなら（寝るのが遅い）
   ▼
[UDE: 朝ごはんを食べない]
   │ なぜなら（起きるのが遅くて時間がない）
   ▼
[Cause: 午前中のエネルギー不足]

[UDE: 授業中に眠くなる]
   │ なぜなら
   ▼
[Cause: 集中力が続かない]
   │ なぜなら
   ▼
[UDE: 成績が下がる]

[UDE: イライラする]
   │ なぜなら
   ▼
[UDE: 友達と衝突する]

ここまでで、「朝の症状」「授業・成績の症状」「気分・人間関係の症状」の3つの枝ができました。一見、全く別々の問題です。

Step3: 3つの枝が「共通の原因」に合流する

ここからがCRTの見せどころ。それぞれの枝をさらに上に辿ると…

「午前中のエネルギー不足」はなぜ？ → 睡眠不足（Cause） 「集中力が続かない」はなぜ？ → 睡眠不足（Cause） 「イライラする」はなぜ？ → 睡眠不足（Cause）

3つの別々に見えた症状が、全部「睡眠不足」という1つの共通原因に合流します。

[Cause: 午前中のエネルギー不足] ─┐
[Cause: 集中力が続かない] ────────┼──► [Cause: 睡眠不足]
[UDE: イライラする] ──────────────┘

そして「睡眠不足」はなぜ？ → 夜更かし（Cause）。夜更かしはなぜ？ → 寝る前にスマホを見てしまう（Cause）。

Step4: Root（根本原因）を特定する

全体のツリーはこうなります。

[UDE: 朝、起きられない]
   ▼
[UDE: 朝ごはんを食べない]
   ▼
[Cause: 午前中のエネルギー不足] ─┐
                                ├─► [Cause: 睡眠不足] ◀── [Cause: 夜更かし] ◀── [Cause: 寝る前にスマホ] ← Root
[UDE: 授業中に眠くなる] ─────────┘
   ▼
[Cause: 集中力が続かない]
   ▼
[UDE: 成績が下がる]

[UDE: イライラする] ──► [UDE: 友達と衝突する] ──►（ここも睡眠不足に合流）
  • 「朝起きられない」「成績が下がる」「友達と衝突する」… 見た目はバラバラの5つの症状
  • でも因果を辿ると、全部が「睡眠不足」→「夜更かし」→「スマホ」という1本の Root に集まる

Root（根本原因）= 夜更かし（寝る前にスマホを見てしまう）

ここで何が変わったか（体験のまとめ）

  • CRTを作る前: 「朝起きる努力をしよう」「勉強を頑張ろう」「友達と仲直りしよう」と、5つの対策がバラバラに浮かぶ（モグラ叩き）
  • CRTを作った後: 「夜更かし」を直せば、5つの症状がまとめて改善し始めると分かる

これがCRTの良さです。 「散らばった問題（UDE）」を因果でつないでいくと、「実は1つの根本原因（Root）で説明できる」という収束が見えてきます。Rootを直すことで、複数の症状をまとめて改善できます。これは、個別にモグラ叩きするよりはるかに効率的です。

ここまでがCRTの意義。 次は Root（夜更かし）をどう解消するか（Unit 8 で）。

8. よくある誤解（Misconceptions）

誤解 正しい理解
「原因が分からなくても、とにかく何か対策すればいい」 原因が分からない対策はモグラ叩き。まず構造を見る（CRT）のが先
「原因を全部直すのが良い」 根本原因1つを直すと複数の症状がまとめて良くなる。全部直すのは非効率
「解決策から考えてOK」 先に「原因（構造）」を特定する。解決策（Injection）は Unit 8
「原因と症状が混ざってOK」 混ざってよいが区別はする。Step1の出発点は「観測できる症状（UDE）」。原因ノード（Cause）はStep2で掘り下げて追加する。区別を意識しないと、Rootが見えなくなる

  • Rootに集中すると、複数の症状がまとめて改善する。これが合理的で効率的な解決

Unit 8 — 演習B（基本編）: 解消 — 蒸発する雲で対立を解体し、根本原因を直す

対象: 中学2年生〜一般社会人 ゴール（L3 Teach-Back）: 蒸発する雲で対立を解体し、対立の前提を外す解消策（Injection）を設計できる。新たな問題（FRT）も確認できる 所要目安: 20〜30分（Unit 7 の続き） 準備: Unit 7 で作ったCRT・演習カード

1. Hook — 「どっちを取るか」の対立

「朝起きられない」を直すために、夜更かしをやめたい。でも…

  • 「スマホを寝る前に見たい」←→「早く寝なきゃいけない」

この2つは対立していますか？ 実は、対立しているように見えて、実は対立していないことがよくあります。これを解く道具が「蒸発する雲」です。

2. 蒸発する雲（Evaporating Cloud）とは

Value（価値）

対立を「どちらかが折れる（妥協）」で解くと、片方が不満を残します。蒸発する雲は、対立の前提を外して「両方かなえられる」道を作るので、雲（対立）が「蒸発」します。

Purpose（目的）

対立している2つの行動の、奥にある「共通の目的」を見つける。

Meaning（意味）

        [目的C] 共通の上位目的
        ／            ＼
  [要求A]              [要求B]
     │                   │
  [行動A]  ←→対立←→  [行動B]
  • 目的C: 両者が本当に望んでいる共通の上位目的
  • 要求A/B: その目的を達成するための条件
  • 行動A/B: 実際にやっていること（これが対立している）

ポイント: 行動AとBが対立していても、目的Cは共通であることがほとんど。

3. 蒸発する雲の書き方（4ステップ）

Step1 対立している2つの行動を書く（A vs B）
Step2 それぞれの行動の「要求」（なぜそれをやるのか）を書く
Step3 その下の「共通の目的」を書く
Step4 対立を「蒸発」させる前提を探す（Injection）

4. 例題（EX1の続き: 朝起きられない）— 解答つき

蒸発する雲を描く

        [目的C] 健康で元気に毎日を過ごしたい（学校生活を楽しみたい）
        ／                                  ＼
  [要求A] 楽しい時間を持ちたい             [要求B] 十分に眠りたい
     │                                         │
  [行動A] 夜遅くまでスマホを見る      ←→   [行動B] 早く寝る

対立しているのは「行動A vs 行動B」。でも目的C（元気に過ごしたい）は共通。

対立の「前提」を探す（ここが肝心）

なぜ行動Aと行動Bが対立するのでしょう？ そこには隠れた前提（思い込み）があります。

前提: 「楽しい時間は夜しかない」「スマホを見る＝夜遅く」

この前提が実は間違っていたら？

Injection（解消策）— 前提を外す

前提（思い込み） それを外す Injection
「楽しい時間は夜しかない」 昼間にスマホを見る時間を決める・楽しい活動を別の時間に作る
「スマホを見る＝夜遅くまで」 スマホの利用時間を制限する（タイマー・自分ルール）
「眠る時間が減っても大丈夫」 睡眠の大切さを知る（遅れの効果: 翌日の集中力）

Injectionは「妥協」ではない。 「楽しさ」と「睡眠」の両方をかなえる新しい仕組み（例: スマホは21時まで、夜は読書に変える）を作ります。こうすると、対立（雲）が消えて、根本原因（夜更かし）が直接解消されます。

5. InjectionとFRT（新たな問題の確認）

Injection（注入・解消策）

根本原因を解消する新しい仕組み・ルール・仕掛け。

  • 根本原因を「直す」のではなく「対立の前提を外す」形にするのがTOC流
  • 例: 「夜はスマホを別の部屋に置く」という仕組み

FRT（Future Reality Tree / 未来問題ツリー）

Injectionを入れたら、新たな問題が生まれないかを確認する。

Injection（例: 夜はスマホを別の部屋に置く）
   │
   ▼
良い結果: 夜更かしが減る → 朝起きられる
   │
   ▼
新たな問題?: 「連絡を見逃す」「夜が退屈」
   │
   ▼
対策: 連絡は朝確認する / 退屈な夜の楽しみ（読書など）を用意

完璧な対策はない。 FRTで「新たな問題」を予想し、その対策まで考えるのがTOCの丁寧さです。

6. Check — 確かめてみよう

  1. 蒸発する雲の「目的C」とは何？
  2. Injectionは「妥協」と何が違う？
  3. FRTは何を確認する道具？

答え（下を見る前に自分で）: 1. 両者が共通に望む上位目的　2. 妥協は片方が諦める。Injectionは対立の前提を外して両方かなえる　3. 解消策が新たな問題を生まないか

7. よくある誤解（Misconceptions）

誤解 正しい理解
「対立はどちらかが折れればいい」 妥協は不満を残す。前提を外せば両方かなえられる
「Injection = 努力・我慢」 努力・我慢ではなく、仕組み（環境）を変える
「解決策を思いつけば終わり」 FRTで新たな問題まで確認するのがTOC流

Unit 8.5 — 参照モードを描く：「このままだとどうなる」を先に見る

対象: 一般社会人〜中学2年生（Unit 9 の直前がおすすめ。中2は Unit 11 へスキップ可） ゴール（L3 Teach-Back）: 問題の変化を過去→現在→未来のグラフ（参照モード）で描き、放置シナリオを人に説明できる 所要目安: 20〜25分 準備: Unit 2（ストック）・Unit 4（時間の遅れ）を読んでいること

1. Hook — 「今」だけ見ると、対策がズレる

職場の問題を聞くと、よくこう言われます。

  • 「最近、会議が増えた」
  • 「今月の売上は伸びている」
  • 「残業はまだ多い」

「今」の数字だけを見ると、「会議を1つ減らそう」「もっと値下げしよう」と、すぐ効く対策に飛びがちです。

でも SD は最初にこう問います。

「このまま何も変えなかったら、過去から現在を経て、未来はどうなる？」

これを 参照モード（Reference Mode） と呼びます。Unit 9 の SD 演習の Step1 です。

2. なぜこれを学ぶのか？（Value）

今だけ見る 参照モードで見る
売上は伸びている → 値下げ成功 利益は減り続けている → 放置すると赤字
会議は多いが大変 仕事の山が増え続ける → さらに破綻
残業はまだある 成功の負担で、さらに残業が増える予測

参照モードは 診断の地図 です。CLD・SFD（Unit 2.5・3.5）で「なぜそうなるか」を描く前に、「何がどう動いているか」を時間軸で固定します。

3. 参照モードの部品（Reveal）

3.1 縦軸・横軸

軸 何を書くか 例
横軸（時間） 過去 → 現在 → 未来 月・週・年
縦軸（変数） たまる量（ストック） または 流れる量（フロー） 利益・未完了仕事・売上

コツ: まず 1〜2変数 に絞る。3本以上は上級者向け。

3.2 線の種類（シナリオ）

線 意味
実線 過去〜現在まで、実際に（または観察として）起きた動き
破線 放置シナリオ — このまま何も変えなかった未来の予測
別色の破線（任意） 介入シナリオ — 対策を入れたときの予測（Unit 9 後半）

Point: 参照モードの核心は 破線の放置シナリオ。「このままだとどうなるか」を先に描く。

3.3 定性的 vs 定量的

種類 いつ使う 描き方
定性的 データが少ない・最初の仮説 上がる／下がる／横ばいを矢印や傾きで
定量的 数値がある 実際の数値をプロット（Excel等でも可）

Unit 9 の演習では、定性的参照モードから始めて十分です。

4. 参照モードを描く5ステップ（Interact）

Step1 変数を1〜2個選ぶ — 何の動きを見る？（ストック優先）
   ↓
Step2 軸を決める — 縦＝変数、横＝時間（単位を書く）
   ↓
Step3 過去→現在を実線で描く — 実際にどう変化したか
   ↓
Step4 放置シナリオを破線で描く — このままだとどうなる？
   ↓
Step5 検証する — 遅れ・複数変数・ストック/フローの区別

Step1 — 変数を選ぶ

ストック（たまる量）を優先する。フロー（売上など）は補助線でもよい。

問題 おすすめの縦軸
会議が多い 未完了の仕事量（ストック）
値下げの罠 利益（ストック）＋ 売上（フロー・補助）
残業が減らない 残業時間 または 仕事の山

Step2 — 軸を決める

縦: 未完了の仕事量（件）
横: 時間（週）

軸ラベルは必ず書く。単位が違う変数を1グラフに重ねるときは、2軸または別グラフに分ける。

Step3 — 過去→現在（実線）

「最近3ヶ月で未完了が増え続けた」→ 右肩上がりの実線。

Step4 — 放置シナリオ（破線）

「会議を減らさないまま」→ 実線の先から、さらに上がる破線。「このままだと破綻に近づく」という仮説を書く。

Step5 — 検証

# 問い
1 縦軸はストックかフローか？ 混同していないか？
2 破線は「何も変えない」未来か？ 対策が混ざっていないか？
3 Unit 4 の遅れ — 対策後の回復はすぐには見えない、と整合しているか？
4 複数変数のとき、因果が分かる配置か？（売上↑・利益↓ など）

やってみよう: 紙に横軸・縦軸を書き、実線と破線を1本ずつ描く。上の SVG と見比べる。

5. 例で定着 — 値下げの罠（Unit 9 例題と接続）

EX9（値下げ）の参照モード:

  • 売上（フロー） 実線: 右肩上がり（値下げで伸びた）
  • 利益（ストック） 実線: じわじわ下降
  • 利益 破線: さらに急落（値下げ競争が続く）

「売上は良いのに儲からない」の正体が、ストック（利益）の参照モードで見える。

7. 介入シナリオを描く（2本目の破線）

放置シナリオ（赤い破線）に加え、対策を入れた未来を 別色の破線 で描きます。

線 意味 色の例
実線 過去〜現在 青
破線① 放置（何も変えない） 赤
破線② 介入シナリオ（対策後の予測） 緑

描くときのルール

  1. 介入は1つに絞る — 「会議を減らす」「定時退社」など、CLD で切るループと対応させる
  2. すぐには効かない（Unit 4）— 介入破線は最初しばらく実線に近く、後から下がる・上がる
  3. 政策抵抗（Unit 9）— 介入破線が放置破線と同じにならないか確認する

例題 — EX4 会議過多：会議を段階的に減らす

  • 赤破線: 会議を減らさない → 未完了がさらに増える
  • 緑破線: 会議の入口を切る → 未完了はまだ増えたあと、遅れて減り始める

やってみよう: 自分の EX4 解答の介入策を1つ選び、緑の破線で「3ヶ月後くらいから下がる」と描いてみる。

例題 — EX9 値下げの罠：差別化で利益率を守る

  • 青実線: 売上（フロー）は値下げで伸び続ける
  • 赤実線＋赤破線: 利益（ストック）は下降し、競争継続で急落
  • 緑破線: 値下げ競争から降り、付加価値で利益率を守る介入（効果は遅れる）

8. Check — 確かめてみよう

  1. 参照モードで最初に描くべき「未来の線」は実線か破線か？
  2. 縦軸に「売上」と「利益」を同時に書くとき、何に注意する？

  1. 何の話か: 「このままだとどうなるか」をグラフで先に見る話

6. 統合例題（EX4: 会議過多）— 参照モード → CLD → SFD 解答つき

「会議が多すぎて仕事が進まない」を、SD 統合ワークフローで一気通しします。

Step1: 参照モード（このままだとどうなる）

縦軸: 未完了の仕事量（ストック）。横軸: 時間（週）。

  • 実線（過去〜現在）: 未完了が増え続けている
  • 破線（放置シナリオ）: 会議を減らさないまま → さらに急増
  • 緑破線（介入）: Unit 8.5 §7 — 会議削減後、遅れて未完了が減る（figures/ref_ex4_intervention.svg）

参照モードで「たまる量が危険な方向に動いている」と先に固定します。

Step2: 因果ループ図（CLD）

Unit 3.5 の手順で、会議の悪循環を CLD にします。

会議の数 ─(＋)→ まとまった仕事時間がない ─(＋)→ 成果物の遅れ ─(＋)→ 進捗確認会議 ─(＋)→ 会議の数

すべて＋ → R1（強化ループ）。会議を増やすほど遅れ、遅れるほど会議が増える。

Step3: ストックフロー図（SFD）

Unit 2.5 の手順で、同じ問題を「量」で描きます。

  • ストック（□）: 未完了の仕事
  • フローIN: 新規タスクの流入
  • フローOUT: 仕事の処理（実働）
  • コンバータ（◇）: 会議時間
  • 情報リンク（点線）: 会議時間 → 仕事の処理（会議が多いと処理が減る）

CLD と SFD の対応:

CLD の変数 SFD での位置づけ
成果物の遅れ 未完了ストックが増える結果
会議の数 会議時間（◇）が処理フローOUTを抑える
まとまった仕事時間がない 処理フローOUTが小さい状態

詳しい写像手順・単位チェックは Unit 9.5 を参照。

Step4: 介入点

6. 例題（EX9: 値下げの罠）— 解答つき

Unit 9 と同じ「値下げの罠」を、今度は TOC の4ステップで解く。

Step1: 制約（ボトルネック）の特定

利益（ストック）を増やすのに、制約は「販売数」か？ それとも「利益率」か？

→ 利益率（1個あたりの儲け） が制約。販売数は増えているのに利益が増えないのだから、遅い・詰まっているのは「利益率」側。

Step2: CRT（根本原因）

[利益が減った]
   ▼
[売上（フロー）は増えたが、費用（フローOUT）も増えた]
   ▼
[1個あたりの利益率が下がった]
   ▼
[値下げした]
   ▼
[「売上を増やす＝値下げ」という思い込み] ← 根本原因

因果の検証（Unit 7 §4.5）: 「値下げ→利益率低下」は確か。でも「売上を増やす＝値下げしかない」は思い込み（第3の原因の見落とし・別の方法がある）。

根本原因 = 「売上（フローIN）＝良し」という見方。利益（ストック）ではなく売上で判断している。

Step3: 蒸発する雲（対立の解体）

[目的C] 長期的に儲け続ける（事業を続ける）
   ／                              ＼
[要求A] 売上を増やしたい          [要求B] 利益率を守りたい
   │                                  │
[行動A] 値下げする            ←→  [行動B] 値段を維持する

共通の目的C: 「長期的に儲け続ける」。実は一致している。

前提（思い込み）: 「売上を増やす = 値下げしかない」

Step4: Injection（前提を外す）

値下げ以外で売上を増やす方法: - 付加価値を上げる（品質・サービス・デザインで差別化） - セット販売・定期購入で客単価を上げる - ボトルネック（EX10）の視点で、儲かる商品に集中する

→ 「売上」と「利益率」の対立が、前提を外すことで蒸発する。

Step5: FRT（新たな問題）

  • 付加価値アップ → 価格に見合わないと思われる？ → 対策: 実績・レビューを可視化
  • セット販売 → 在庫が増える？ → 対策: 需要予測・限定数でリスク抑制

Step6: Teach-Back（SD の答えと並べて）

  • SD の答え（Unit 9）: 「利益率の負のループが遅れて効く。利益（ストック）を見て、利益率のループを強め、効果を待つ」
  • TOC の答え（このUnit）: 「制約は利益率。根本は『売上＝良し』の思い込み。値下げ以外で売上を増やす仕組み（Injection）を作る」

→ 同じ問題でも、SD は「なぜ・いつ」を、TOC は「どこを・どう」を答える。

7. 例題（EX10: ボトルネックと価格）— 解答つき

スループット会計（TOC の核心）。カード exercises/ex10_bottleneck_pricing.md を参照。

計算

製品 粗利 ボトルネック時間 1分あたり
A 1,000−500 = 500円 10分 50円/分
B 800−400 = 400円 5分 80円/分
  • Aだけ（480÷10=48個）: 48×500 = 24,000円
  • Bだけ（480÷5=96個）: 96×400 = 38,400円

→ 価格の高いAより、ボトルネック1分あたりの儲けが大きいBを優先すると、全体の利益が大きい。

なぜこれが大事か

「1個の儲け」ではなく「制約（ボトルネック）の時間あたりの儲け（スループット）」で判断する。限られた資源（機械時間）を最も効率よくお金に変える。これが TOC ならではの価格・優先の考え方。

答え（下を見る前に自分で）: 1. 今の構造（制約・根本原因）　2. 「売上＝良し」という思い込み（売上で判断し、利益を見ていない）　3. ボトルネック1分あたりの利益（スループット）　4. SDは「なぜ・いつ」（時間的構造）、TOCは「どこを・どう」（制約と根本原因）。見るレンズが違うと見えるものが違う

10. Teach-Back — 素人に説明しよう

自分の選んだ題材で、TOC の答えを Unit 9 の SD の答えと並べて説明しよう。テンプレ:

  1. 何の話か
  2. 部品は何か（制約・CRT・蒸発する雲・Injection・FRT から使ったもの）
  3. どう繋がるか（制約 → 根本原因 → 対立の解体 → 解消の流れ）
  4. 図や計算はどこを見ればいいか
  5. SD（Unit 9）とどこが違うか ← このUnitの要
  6. 素人への一言（比喩1つ）

まとめ（Takeaway）

  • TOC の切り口 = 問題を今の構造（制約・根本原因） で見る
  • 4つのステップ: 制約 → CRT → 蒸発する雲 → Injection・FRT
  • スループット会計: 制約の時間を、1分あたりの儲けが大きい方に使う
  • 同じ問題でも、SD と TOC では見える答えが違う
  • 次回は、2つの切り口を統合して「システム思考」としてまとめる

Unit 11 — 対比と抽象化：「システム思考」を自分の言葉にする

対象: 全員（中2〜一般社会人） ゴール（L3 Teach-Back）: SD と TOC の切り口の違いを説明でき、両方を統合した「システム思考」を自分の言葉でまとめ、新しい問題へ応用できる 所要目安: 30〜40分 準備: Unit 9・10 で作った「同じ問題」の2つの解答

1. Hook — 同じ問題を2つのレンズで見た結果

Unit 9（SD）と Unit 10（TOC）で、同じ問題を2つの切り口で解きました。例えば「値下げの罠」なら：

SD の答え（Unit 9） TOC の答え（Unit 10）
見たもの 売上と利益の時間差・2つのループ・政策抵抗 制約（利益率）・根本原因・対立
答えたこと 「なぜ・いつ」利益が減るか 「どこを・どう」直すか
解決の形 利益率のループを強め、効果を待つ 値下げ以外で売上を増やす仕組み

同じ問題なのに、見え方が違いました。 これがこのUnitの出発点です。2つのレンズは「どちらが正しいか」ではなく、どちらも正しい。見ている面が違うのです。

2. なぜこれを学ぶのか？（Value）

Unit 1〜10 で、たくさんの道具を学びました。

  • ストックとフロー・フィードバック・時間の遅れ（SD）
  • ボトルネック・5ステップ・CRT・蒸発する雲（TOC）

道具が増えると、「どの道具を、いつ使うか」 が分からなくなります。このUnitの目的は、道具を「システム思考」という1つの考え方として統合し、「この問題にはこの切り口」 と選べるようにすることです。

3. SD と TOC の関係（Reveal）

3.1 2つの切り口の違い

軸 SD（システムダイナミクス） TOC（制約理論）
問い 構造は時間とともにどう動くか どこを今直せば全体が良くなるか
見るもの ループ・ストック・フロー・遅れ 制約・根本原因・対立
得意 「なぜそうなるのか」を説明 「どこを直すか」を特定
未来 放置の結果を予測（参照モード） あまり見ない
解決 ループを切る・フローを変える 制約を直す・前提を外す
主な道具 ストックフロー図・ループ図 5ステップ・CRT・蒸発する雲

3.2 相補関係（補い合う）

SD: 「なぜ・いつ」問題が起きるか ──→ 構造の全体像が見える
        │
        ▼
TOC: 「どこを・どう」直すか ────→ 改善の焦点が決まる
  • SD だけだと「構造は分かったが、どこから手をつければ？」となる
  • TOC だけだと「直す場所は分かったが、周りの動きへの影響（時間差・副反応）が見えない」

両方持つと最強。 SD で構造を見て、TOC で制約を直す。

3.3 同じ構造の別の顔

実は、SD と TOC は同じことを別の言葉で言っている部分があります。

SD の言葉 TOC の言葉
正のループ（成長） 成長の限界の「伸びる側」
負のループ（調整・制約） 制約（ボトルネック）
ループを切る 制約を直す
政策抵抗（対策が打ち消される） 対立の前提（対策が対立を生む）

違う道具でも、見えている「現実の構造」は共通。 これがシステム思考の力です。

4. 統合フレーム：「システム思考」のワンストップ（Reveal）

問題にぶつかったときの、統合した流れを作ります。

   ↓
Step2 構造を見る（SD）: ストック・フロー・ループ・遅れを図で描く
   ↓
Step3 制約を特定する（TOC）: どこが全体を決めているか
   ↓
Step4 根本原因を特定する（TOC）: CRT + 因果の検証
   ↓
Step5 対立を解体する（TOC）: 蒸発する雲 → 前提を外す
   ↓
Step6 介入策を設計する（SD+TOC）: ループを切る・フローを変える・前提を外す

これを「システム思考のフルコース」と呼びましょう。Unit 7〜10 でバラバラに練習したステップが、ここで1つの流れになります。

Unit 12 — SD の強みが発揮される大規模問題：巨大で複雑な問題を「構造」で読む

対象: 一般社会人〜大学学部生レベル（中2は興味があれば読んでよい） ゴール（L3 Teach-Back）: 身近な問題では見えなかった SD の真価（複雑系の構造理解）を、4つの実例で体験し、「なぜこれが SD にしかできないか」を説明できる 所要目安: 各 SDX を 15〜20分 × 4 位置づけ: 任意の番外編。Unit 11（対比と抽象化）の後に読むのがおすすめ

1. Hook — 「身近な問題」では測れなかった SD の実力

これまでの演習（Unit 1〜11）は、どれも「身近な問題」でした。

  • お風呂の水位・テスト勉強・部活・会議・残業・値下げ…

これらの問題では、「どこを直すか」が比較的はっきりしていて、TOC や OR（最適化）の切り口が強く見えました。SD は「構造の理解」に回ることが多かったと思います。

でも、世の中にはこんな問題があります。

気候変動。感染症のパンデミック。都市の成長と衰退。企業の興亡。

これらは複雑で、時間がかかり、要素が絡み合い、単純な最適解が存在しません。 こういう問題こそ、SD の出番です。このUnitでは、SD が「どんな問題を得意とするか」「何をどう見せてくれるか」を実例で体験します。

2. SD が得意とする問題の特徴（Value）

SD が真価を発揮する問題には、共通の特徴があります。

特徴 意味 例
複雑 要素がたくさん絡み合っている 気候・経済・社会
時間が長い 効果が何年・何十年後に出る 気温上昇・少子化
循環 原因と結果が相互に作用する 環境と経済
非線形 2倍にすれば2倍、とは限らない 感染症の爆発的流行
最適解がない 正しい答えが1つに定まらない 政策・戦略

SD は「解を出す」道具ではなく「構造を理解する」道具。 だからこそ、最適解のない複雑な問題で本領を発揮します。

3. OR（解く）と SD（理解する）の使い分け（Reveal）

OR（オペレーションリサーチ） SD（システムダイナミクス）
問い 最適な解は何か なぜそうなるのか
得意 境界が明確・解が存在する問題 複雑・循環・時間が長い問題
例 生産計画・輸送・在庫・スケジュール 気候・感染症・都市・経営戦略
答え 数値（この計画が最適） 構造（このループが原因）

使い分けのコツ:

問題の境界が明確で、最適解が求められる → OR
問題が複雑で、原因と結果が循環している → SD

ただし、これは「どちらか」ではありません。 複雑な問題でも、その中の一部分（例: 在庫管理）は OR で解ける。全体を SD で理解し、部分を OR で解くのが本格的な使い方です。

SDX1 — 気候変動：温室効果ガスと気温の「増幅ループ」

1. 事例の概要

地球の平均気温が上がり続けています。その原因とされるのが「温室効果ガス（CO₂など）」の増加です。

2. SD の構造（読み取り方）

ストックとフロー

CO₂の排出（フローIN）──▶ [大気中のCO₂（ストック）] ◀── 吸収（フローOUT）
                             ↑ ここが「たまっている」
  • ストック: 大気中の CO₂（たまっている量）
  • フローIN: 工場・車・森林破壊による排出
  • フローOUT: 森林・海洋による吸収

読み取り方のポイント: 問題は「排出量」だけでなく「たまっている CO₂の量（ストック）」です。排出を少し減らしても、ストック（たまっている量）は減りません。減るには時間がかかる。

フィードバックループ

正のループ（増幅）:

気温が上がる
   ▼
氷が溶ける（白い氷が減る → 太陽光を反射しなくなる）
   ▼
地球がより熱を吸収する
   ▼
さらに気温が上がる ←（正のループ・自己増幅）

これは「暴走の可能性」を示す構造。気温上昇が気温上昇を呼ぶ、雪だるま式の危険なループです。

3. 時間の遅れ（意味）

SD が見せる重要なことのひとつが「時間の遅れ」です。

CO₂を排出（今） →（数十年の遅れ）→ 気温上昇が顕在化

今日排出した CO₂ の影響は、数十年後に出ます。 だから「今、まだ大丈夫」と錯覚する。SD はこの遅れを見える化します。

4. 意義（なぜ SD で見る価値があるか）

  • OR（最適化）では扱えない: 気候の「最適なCO₂排出量」を数値で出しても、現実の政策はそれだけで決まりません（政治的・経済的・倫理的要素が絡む）
  • SD は「構造」を示す: 「なぜ気温上昇が止まらないのか」「どのループを切れば止まるのか」を、誰にでも見える図で説明できる
  • 政策の副反応を予見: 「経済成長を優先」すれば CO₂ が増え、その影響が後から返ってくる（政策抵抗・Unit 9）

SD の答え: 「CO₂の排出（フロー）を減らす」だけでなく、たまっている CO₂（ストック）を減らす（吸収を増やす）ことと、増幅ループを切る（氷の融解・森林破壊を止める）ことが必要。

SDX2 — 感染症の流行（SIR モデル）：なぜ爆発的に広がるのか

1. 事例の概要

新型の感染症が、あっという間に世界中に広がりました。最初は「数人」だったのが、数週間で「数万人」に。

2. SD の構造（読み取り方）

ストックとフロー（SIR モデルの骨格）

感染者を「たまるもの」で考えると、次の3つの「たまり」があります。

[S: 感受性者（かかっていない人）] ──感染──▶ [I: 感染者] ──回復──▶ [R: 回復者（免疫あり）]
ストック 意味
S（感受性者） まだかかっていない・うつる可能性がある人
I（感染者） 現在感染している人
R（回復者） 治って免疫を持った人（もううつさない）

正のループ（爆発的拡大）

感染者（I）が多い
   ▼
1人がうつす相手の数が多い
   ▼
新たな感染者が増える
   ▼
感染者（I）がさらに増える ←（正のループ）

これが「爆発的」に広がる理由。 感染者が増えるほど、新たな感染者を生むスピードも上がる。非線形（2倍→4倍→16倍…）の増え方になります。

負のループ（抑える力）

感染者が増える
   ▼
対策（マスク・距離・ワクチン）が強まる
   ▼
感染が減る ←（負のループ・バランス）

さらに、R（回復者）が増えると、うつる相手（S）が減るので、感染は自然に収束していきます（集団免疫）。

3. 読み取り方のポイント

  • なぜ最初「大丈夫」に見えたか: 感染者が少ないうちは、正のループもゆっくり。指数関数的な増加（Unit 3 発展編の $e^{rt}$）は「遅れて」爆発する
  • 対策の意味: マスク・距離・ワクチンは、正のループ（拡大）を抑える「介入点（Unit 9）」
  • 時間の遅れ: 感染から発症・報告まで遅れがある → 対策が遅れる → さらに拡大

4. 意義（なぜ SD で見る価値があるか）

  • OR だけでは不十分: ワクチンを「何本配るのが最適か」は OR で解けるが、「いつ・どの対策が効くか」は、感染のダイナミクス（時間的振る舞い）を見ないと分からない
  • SD は「なぜ爆発するか」を説明: 正のループの構造が見えると、早期対策の重要性が自明になる
  • 政策の副反応を予見: 早く開けすぎると再拡大（対策と感染のタイミングの遅れ）

SD の答え: 「感染者数（I のストック）」を追うだけでなく、正のループ（拡大）をどう抑えるか（介入点）と、遅れを理解して、早めに・十分に対策することが鍵。

5. シミュレーションで SIR を動かす（L5 入口）

SIR モデルは次の式で書けます（$N$ は総人口）：

$$ \frac{dS}{dt} = -\beta \frac{SI}{N},\quad \frac{dI}{dt} = \beta \frac{SI}{N} - \gamma I,\quad \frac{dR}{dt} = \gamma I $$

コンピュータでは、また オイラー法（少しずつ時間を進めて更新）で曲線を描きます。

静的な結果（ビルド時に Python で計算）

インタラクティブ — β と γ を変える

感染率 $\beta$ を上げるとピークが早く・高くなります。回復率 $\gamma$ を上げるとピークが抑えられます（マスク・距離・ワクチンの効き方のたとえ）。

β を上げると感染者 I のピークが早く・高くなります。γ を上げるとピークが抑えられます。

やってみよう: $\beta$ を上げて I のピークがどう変わるか見る → Unit 9 の「介入点（拡大ループを抑える）」と対応づける。

SDX3 — 都市の成長と限界：なぜ発展が止まるのか

1. 事例の概要

ある都市が急速に発展しました。企業が集まり、人口が増え、活気があふれました。しかし、ある頃から成長が止まり、問題が増え始めました。

発展 → 人が集まる → さらに発展（正のループ）
        ↓ でも…
        インフラが限界 → 渋滞・家賃高騰・環境悪化

2. SD の構造（読み取り方）

正のループ（成長）

都市が魅力的 → 企業・人が集まる → 経済が発展 → さらに魅力的に

これは Unit 3 で学んだ成長の正のループ。最初は順調に伸びます。

負のループ（限界 = 抑制）

人口が増える
   ▼
交通が渋滞する・家賃が高騰する・環境が悪化する
   ▼
都市の「住みやすさ」が下がる
   ▼
人が離れる・企業が移転する → 成長が止まる

これは Unit 3 発展編で学んだ『成長の限界』。正のループ（伸びる）と、負のループ（抑える）のぶつかり合いです。

時間の遅れ（厄介な点）

人口が増える（今） →（数年〜十数年の遅れ）→ インフラ不足が顕在化

インフラ整備は後からしか追いつきません。 「今は大丈夫」と感じていても、実は限界に近づいている。SD はこの遅れを見える化します。

3. 読み取り方のポイント

  • 成長が止まるのは「努力が足りない」のではなく「構造（制約）」が原因（Unit 5 のボトルネックと同じ考え方）
  • ボトルネック: 都市の成長を止めているのは「インフラ・住居・環境」のどれ？
  • 介入点: 負のループ（住みにくさ）を緩和する（交通整備・住居供給・環境対策）

4. 意義（なぜ SD で見る価値があるか）

  • OR の限界: 「道路を何本作れば最適か」は OR で解ける。しかし「都市がなぜ衰退するか」という構造全体は、ループで見る必要がある
  • SD は「都市の未来」を予測する: 人口・インフラ・環境のループを組むと、「このままだとどうなる」（Unit 9 の参照モード）を描ける
  • 成長の限界の一般性: 同じ構造が「都市」「企業」「生物の増殖」などに共通して現れる（抽象化・Unit 11）

SD の答え: 都市の発展は「正のループ（成長）× 負のループ（限界）」の構造。成長を持続するには、限界（インフラ・環境）を先回りして直すこと。放置すると、成長は頭打ちどころか衰退に転じる。

SDX4 — 経営戦略：規模の経済と衰退の罠

1. 事例の概要

ある会社が事業を拡大しています。規模が大きくなれば、コストが下がり、さらに市場を取れる。しかし、ある時点から「大きくなるほど動きが鈍る」現象が起き始めました。

規模拡大 → コスト低下 → 競争力向上 → さらに拡大（正のループ）
        ↓ でも…
        組織が複雑化 → 意思決定が遅い → 衰退の兆し

2. SD の構造（読み取り方）

正のループ（規模の経済）

生産量が増える
   ▼
1個あたりのコストが下がる（規模の経済）
   ▼
価格競争力が上がる → シェアが増える
   ▼
さらに生産量が増える ←（正のループ）

これは「勝ち続ける」構造。大きな会社がさらに強くなる理由です。

負のループ（規模の不経済・組織の鈍化）

組織が大きくなる
   ▼
部門が増え、意思決定の経路が長くなる
   ▼
決断が遅くなる・現場の声が届かない
   ▼
市場の変化に乗り遅れる → 競争力が落ちる
   ▼
（成長が止まる・衰退する）

これは 『成功の逆効果』（Unit 3・EX5 と同じ構造）。「成功（規模拡大）」が「次の成功を妨げる（組織の鈍化）」を生みます。

政策抵抗（厄介な点）

「リストラして効率化しよう」「上場して資本を集めよう」という対策は、短期的には効くが、組織の鈍化（負のループ）を根本からは直さない。対策が既存ループに吸収される（Unit 9 の政策抵抗）。

3. 読み取り方のポイント

  • 企業の成長は「正のループ（規模の経済）× 負のループ（組織の鈍化）」の綱引き
  • ボトルネック: 今、成長を止めているのは「コスト」か「組織の意思決定」か「市場の変化」か
  • 介入点: 組織の鈍化ループを切る（意思決定を現場に委ねる・部門間の壁をなくす）

4. 意義（なぜ SD で見る価値があるか）

  • 経営は「最適解」がない: 「何%成長するのが最適」と数値で出しても、実際の経営は競争・組織・文化が絡み合う
  • SD は経営の「構造」を診断する: 「なぜ大きくなると鈍るのか」「どのループが今効いているか」を見える化する（フォレスターが SD を生んだのは、もともと経営分析のため）
  • 企業の興亡は繰り返す: この構造は、多くの企業で何度も繰り返される（抽象化・型の発見）

SD の答え: 経営は「規模の経済（正）と組織の鈍化（負）の綱引き」。成長を持続するには、正のループだけを追わず、負のループ（組織の鈍化）を先回りして直すことが必要。大きくなるほど、それを防ぐ仕組みが要る。

まとめ：SD の強みが4つの実例で見えたもの

SDX テーマ 中心の構造 SD が示したこと
1 気候変動 正のループ（増幅）・時間の遅れ 排出量より「たまっている量」。増幅ループを切る
2 感染症 正のループ（爆発）・ストック（SIR） なぜ爆発するか。介入点と遅れ
3 都市 成長の限界（正×負） 成長が止まるのは構造（制約）。先回り
4 経営 規模の経済 × 組織の鈍化 大きくなるほど鈍る。負のループを直す

共通して見えた「SD ならでは」の強み

  1. 時間の遅れを見える化する — 今の問題の原因が、何年・何十年前にあるか
  2. 循環する構造を見える化する — 「AだからB、BだからA」の相互依存
  3. 非線形（爆発・暴走）を説明できる — 2倍→4倍→16倍の世界
  4. 政策の副反応（政策抵抗）を予見する — 対策が構造に吸収される
  5. 最適解のない問題でも「構造」を示せる — OR が得意としない領域

OR は「この解が最適」と答え、SD は「この構造が原因」と答える。 複雑で大きな問題には、この2つを合わせて使うのが本格的。SD を知ることは、その土台を手に入れることです。

B1 — 変化率と割合：どれだけの速さで変わる？

対象: 発展編に進む中学2年生〜 ゴール: 「変化の割合」＝（変化した量）÷（かかった時間）を説明でき、例で計算できる 所要目安: 10分 前提: 中学1・2年生の割合・比例の復習

1. なぜこれを学ぶのか

システムダイナミクスでは「どれだけ速く変わるか」がすべての中心です。まずは、その基本の道具「変化の割合」を確認します。

2. 変化の割合とは

「物事がどれだけの速さで変わるか」を表す数です。

$$ \text{変化の割合} = \frac{\text{変化した量}}{\text{かかった時間}} $$

例: 5分で気温が3℃上がった → 変化の割合 = 3 ÷ 5 = 0.6℃/分

言葉 意味
変化した量 始めと終わりの差
かかった時間 その変化にかかった時間
単位 「1分あたり・1時間あたり」の量

3. 例で確かめる

例1: 貯金 — 4か月で8,000円増えた → 8,000 ÷ 4 = 2,000円/月

例2: 走る距離 — 3秒で12m進んだ → 12 ÷ 3 = 4m/秒（これが「速さ」）

実は「速さ」も「変化の割合」の1つです。距離の変化 ÷ 時間。

4. Check — 確かめてみよう

  1. 6秒で18m走った。変化の割合（速さ）は？
  2. 2時間で10ページ読んだ。1時間あたり何ページ？
  3. 気温が「1時間で−2℃」変化した。変化の割合は正？ 負？

答え: 1. 3m/秒　2. 5ページ/時間　3. 負（下がった）

5. まとめ

  • 変化の割合 = 変化した量 ÷ かかった時間
  • 「速さ」も「増える量」も全部これ
  • 次はこれを使って「関数とグラフ」を見る

B2 — 関数とグラフ：変化の割合を見える化する

対象: 発展編に進む中学2年生〜 ゴール: 関数のグラフを読み、傾き＝変化の割合であることを説明できる 所要目安: 10分 前提: B1（変化率と割合）

1. なぜこれを学ぶのか

変化の様子は、式よりグラフで見ると一目で分かります。「時間の経過とともに、量がどう変わるか」をグラフにすると、システムの動きが直感的に見えます。

2. 関数とは

一方（時間など）を決めると、もう一方（量）が1つに決まる関係。

$$ y = \text{変化の割合} \times t $$
  • $t$ … 時間（横軸）
  • $y$ … 量（縦軸）
  • 変化の割合が大きいほど、グラフの傾きが急

3. グラフで見る「変化の割合」

y（量）
│            ／ 変化の割合 大（傾き急）
│         ／
│      ／
│   ／  ／ 変化の割合 小（傾きゆるい）
│／
└──────────── t（時間）

傾き＝変化の割合。 グラフが急なほど、速く変わっている。

  • 右上がり（傾き 正）→ 増えている
  • 右下がり（傾き 負）→ 減っている
  • 水平（傾き 0）→ 変わっていない

4. お風呂の水位をグラフで見る

Unit 2 の発展編では、水位が「入り − 出」で決まると学びます。グラフで言うと：

入りと出の関係 傾き グラフ
入り > 出 正 右上がり
入り < 出 負 右下がり
入り = 出 0 水平

グラフの「傾き」が、そのまま変化の割合なのです。

5. Check — 確かめてみよう

  1. グラフが右上がりのとき、量は増えている？ 減っている？
  2. 傾きが急＝変化の割合は大きい？ 小さい？
  3. 水平なグラフの傾きは？

答え: 1. 増えている　2. 大きい　3. 0（変化なし）

6. まとめ

  • 関数 = 時間と量の対応関係
  • グラフの傾き = 変化の割合
  • 傾きの正・負・0 = 増加・減少・横ばい
  • 次は「傾き」を瞬間ごとに測ることを考える

B3 — 瞬間の変化率：「平均」から「瞬間」へ

対象: 発展編に進む中学2年生〜 ゴール: 「平均の変化率」と「瞬間の変化率」の違いを説明できる 所要目安: 10分 前提: B1（変化率と割合）・B2（関数とグラフ）

1. なぜこれを学ぶのか

B1 で「変化の割合」を学びました。しかし、あれは「平均」でした。実際の物事は途中で速くなったり遅くなったりします。「今この瞬間の速さ」 を測れると、物事の動きをもっと正確に分かります。

2. 平均と瞬間の違い

平均の速さ: 全体の距離 ÷ 全体の時間

例: 50kmを1時間で走った → 平均50km/h。でも途中は渋滞で止まったり、高速で走ったりしていた。

瞬間の速さ: 「この瞬間、どれだけの速さで動いているか」（車のスピードメーターが示す値）

3. 瞬間をどう測るか：コマ送りの考え方

動画のコマ送りを想像してください。

  • 1コマずつ時間を細かく区切る
  • 区切りを細かくすればするほど、その瞬間の速さに近づく
  • 時間の区切りを「ほんの少し（瞬間）」まで細かくしたときの速さ = 瞬間の変化率
$$ \text{瞬間の変化率} \approx \frac{\text{ほんの少しの変化量}}{\text{ほんの少しの時間}} $$

4. 記号で表す

この「ほんの少しの時間」を $dt$、「ほんの少しの量の変化」を $d(\text{量})$ と書きます。

$$ \frac{d(\text{量})}{dt} = \text{瞬間の変化率}（＝\text{増える速さ}） $$

これは B5 で出てくる d(水位)/dt の形です。もう、すでに微分方程式の左辺が読めるわけです。

5. Check — 確かめてみよう

  1. 「平均の速さ」と「瞬間の速さ」の違いを一言で言うと？
  2. $dt$ は「ほんの少しの何」を表す？
  3. スピードメーターが示すのは平均？ 瞬間？

答え: 1. 平均は全体、瞬間は今この時点　2. 時間　3. 瞬間

6. まとめ

  • 平均の変化率は「全体の割り算」
  • 瞬間の変化率は「時間を限りなく細かくして測った速さ」
  • $d(\text{量})/dt$ は瞬間の変化率。B5 の式の左辺がこれ

B4 — 微分の意味：「変化する速さ」を測る道具

対象: 発展編に進む中学2年生〜 ゴール: 微分が「瞬間の変化率を求める道具」であることを説明できる。計算は最小限 所要目安: 10分 前提: B1〜B3

1. なぜこれを学ぶのか

「瞬間の変化率」を系統的に扱う数学の道具が微分です。システムダイナミクスでは、微分で「物事が今どれだけの速さで変化しているか」をいつでも記述できます。難しい計算をする必要はありません。「微分は何をする道具か」のイメージが分かれば十分です。

2. 微分とは

微分 = 「瞬間の変化率」を求める道具

ある量 $y$ の変化を時間 $t$ で測るとき、瞬間ごとの変化の速さ（=傾き）を求めるのが微分です。

$$ \text{微分} = \frac{d(\text{量})}{dt} = \text{瞬間の変化率} = \text{グラフの傾き} $$
言葉 意味
微分する 瞬間の変化率を求めること
導関数 微分して得られる「変化の速さ」の式
$d/dt$ 「時間で微分する」という記号

3. 具体例：水位グラフの傾き

お風呂の水位グラフがあったとします。

  • 傾きが急な場所 → 水位が速く増えている（微分が大きい）
  • 傾きが水平な場所 → 水位が変わらない（微分が0）
  • 傾きが右下がり → 水位が減っている（微分が負）

「微分」＝「グラフの傾きを各瞬間ごとに教えてくれる関数」 と覚えておけば十分です。

4. 微分方程式への橋渡し

B3 で学んだ形に、微分を使うと：

$$ \frac{d(\text{ストック})}{dt} = \text{入り} - \text{出} $$

これが「ストックの瞬間の変化率 = 入り − 出」という意味です。B5 で詳しく読みます。

5. Check — 確かめてみよう

  1. 微分は何を求める道具？
  2. グラフの傾きが0のとき、微分は？
  3. $\frac{d(\text{貯金})}{dt}$ は何を表す？

答え: 1. 瞬間の変化率　2. 0（変化なし）　3. 貯金が増える速さ

6. まとめ

  • 微分 = 瞬間の変化率を求める道具
  • 微分した結果（導関数）= グラフの各点の傾き
  • これで B5 の微分方程式を読む準備が整った

B5 — 微分方程式の第一歩：d(水位)/dt = 入り − 出

対象: 発展編（大学レベル）に進む中学2年生〜 ゴール: d(ストック)/dt = 入り − 出 の式を「言葉のルールを正確にしたもの」として読み解ける 所要目安: 10〜15分 前提: B1（変化率と割合）・B2（関数とグラフ）・B3（瞬間の変化率）・B4（微分の意味）

1. なぜこの式が出てくるのか

Unit 2 発展編で、お風呂の水位の変化は次の式で書けると説明しました。

$$ \frac{d(\text{水位})}{dt} = \text{入り} - \text{出} $$

いきなり記号が出てくると怖いかもしれませんが、中身は Unit 2 基本編でやった「水位の変化 = 入り − 出」と同じです。このUnitの目的は、この式を「読める」ようになること。計算はしません。

2. 記号を1つずつ読む

d とは何か

d は「ほんの少しだけ変化する」という印です。d(水位) は「水位のほんの少しの変化」。

dt とは何か

t は「時間」。dt は「ほんの少しの時間の変化」= 瞬間。

d(水位)/dt とは何か

「ほんの少しの時間」の間に「水位がどれだけ変化したか」= 水位が増える速さ。

d(水位)/dt = 水位が増える速さ（＝単位時間あたりの水位の変化）

3. 式全体を言葉に直す

$$ \frac{d(\text{水位})}{dt} = \text{入り} - \text{出} $$

左辺（速さ）と右辺（入り引く出）を言葉にすると：

水位が増える速さ = 入ってくる水 − 出ていく水

これは Unit 2 基本編のルールと一字一句同じです。数式は、長い説明を省略した「略記号」にすぎません。

4. 3つの場合を式で確かめる

場合 式の右辺 左辺 d(水位)/dt 意味
入り > 出 正の数 正 水位は増える速さがプラス（上がる）
入り < 出 負の数 負 水位は増える速さがマイナス（下がる）
入り = 出 0 0 水位は変化しない（横ばい）

右辺の「正・負・0」が、そのまま左辺の「上がる・下がる・変わらない」を決めています。

5. なぜ「微分方程式」と呼ばれるのか

「変化の速さ」を含む式のことを微分方程式と呼びます。d(水位)/dt が入っているからです。

  • 微分 … 「変化の速さ」を扱う数学の道具（B4で学んだ）
  • 方程式 … 未知のものを求める式
  • 微分方程式 … 「変化の速さ」についての式

システムダイナミクスでは、ほぼすべてのモデルがこの形で書かれます。この1本の式を読めるようになると、あとのユニットの数理が全部つながってきます。

6. Check — 確かめてみよう

  1. d(貯金)/dt = 収入 − 支出 という式があったとき、d(貯金)/dt は何を表す？
  2. この式で「貯金が減っている」とき、右辺は正？ 負？
  3. 「フォロワーが横ばい」のとき、d(フォロワー)/dt はいくつ？

答え（下を見る前に自分で）: 1. 貯金が増える速さ（単位時間あたりの貯金の変化）　2. 負　3. 0

7. Teach-Back — 説明しよう

素人に次のように説明してみよう。

「お風呂の水位が増える速さは、蛇口から入る量から排水口に出る量を引いたものだよ。それを短く書くと、d(水位)/dt = 入り − 出 になるだけ。難しくないよ」

  1. 何の話か: 「変化の速さ」を式で書く話
  2. 部品は何か: d(水位)/dt（増える速さ）・入り・出
  3. どう繋がるか: 速さ = 入り − 出
  4. よくある誤解: 微分方程式は「難しい数学」ではなく「言葉のルールの略記」
  5. 素人への一言: 「お風呂の水位だよ。速さは入りから出を引いたもの」

B6 — 指数成長・減衰と e・ln：倍々の数理

対象: 発展編に進む中学2年生〜 ゴール: 「倍々ゲーム＝指数成長」のグラフの形を説明でき、$e$・$\ln$ の意味を直感的に言える 所要目安: 10〜15分 前提: B1〜B5（特に B4 の微分・B5 の微分方程式）

1. なぜこれを学ぶのか

Unit 3 発展編で、正のループは「今の量に比例して増える」と学びます。その結果が指数成長です。ここでは、その数理の顔ぶれ（$e$・$\ln$）を直感的に紹介します。計算は最小限です。

2. 倍々ゲーム＝指数成長

「毎年2倍になる」貯金を想像してください。

年数 量（1万円スタート）
0年 1万円
1年 2万円
2年 4万円
3年 8万円
10年 1,024万円

増え方がどんどん加速します。この「加速しながら増える」形が指数成長です。

量
│          ／
│        ／   ← 加速度的に右上がり
│      ／
│    ／
│  ／
│／
└────────── 時間

3. 比例して増える＝今の量が大きいほど速く増える

「増える速さ」が「今の量」に比例するとき、これを数式で書くと：

$$ \frac{d(\text{量})}{dt} = r \times \text{量} $$
  • $r$ … 増えやすさ（例: 年利・感染率）
  • 量が大きいほど、右辺が大きい = 速く増える

4. $e$ とは何か

この式を解くと、量は次の形になります：

$$ \text{量}(t) = \text{量}(0) \times e^{r t} $$ $e$

は約 2.718… の特別な数です。円周率 （3.14…）と同様に、数学で何度も登場する「自然な数」なので、自然対数の底（しぜんたいすうのてい）と呼ばれます。

覚えるのは次の1点で十分です：

$e^{r t}$ は「指数成長」の形。$r$ が正なら爆発的に増え、$r$ が負なら減っていく。

5. $\ln$ とは何か

$\ln$

（ログ・エルエヌ）は「何年で何倍になるか」を答える逆の道具です。

  • 指数: $e^{r t}$ が「時間から量」を出す
  • $\ln$: 「量から時間」を出す（逆方向）

例: 「$e^{r t}$ が $x$ になるのは、$t = \dfrac{\ln x}{r}$」というように使う。

直感的には「倍になるまでの時間」を計算するための道具、と覚えておけば十分です。

6. 減衰（$r < 0$）

$r$

が負のとき、量は減っていきます（指数減衰）。

$$ \text{量}(t) = \text{量}(0) \times e^{r t} \quad (r < 0) $$ $\pi$

例: 薬の体内濃度・熱いお湯の温度・風船の空気。減り方は「最初は速く、だんだん緩やかになる」曲線です。

7. Check — 確かめてみよう

  1. 指数成長のグラフの形は？
  2. $e$ は約いくつの数？
  3. $r$ が負のとき、$e^{r t}$ はどうなる？

答え: 1. 加速度的に右上がり　2. 2.718…　3. 減っていく（指数減衰）

8. まとめ

  • 倍々ゲーム = 指数成長（$e^{r t}$）
  • 今の量に比例して増える → 加速する曲線
  • $r$ が正なら爆発、負なら減衰
  • $\ln$ は逆方向（倍になる時間）を出す道具
  • 次はこれを使って Unit 3 発展編（正のループ＝指数成長）を読む

EX10 — ボトルネックと価格：どの製品を優先する？（スループット会計・TOC視点）

対象: 社会人　使う要素: スループット会計・制約（TOC） 配置: Unit 9（選択式・解答なし）

シチュエーション

Jさんの工場では、製品Aと製品Bを同じ機械（ボトルネック）で作っています。この機械は1日8時間しか動けません。

製品 1個の価格 1個の変動費 ボトルネック使用時間
A 1,000円 500円 10分
B 800円 400円 5分

需要はどちらもたくさんありますが、機械の時間が足りません。「Aのほうが価格が高いから、Aを優先しよう」という意見と、「Bのほうが1個あたりの儲け（粗利）が大きいからBだ」という意見があります。

問題（UDE）の列挙

例:

  • UDE1: 機械の時間が足りない（ボトルネック）
  • UDE2: どちらを優先するかで意見が割れる
  • UDE3: 優先を間違えると、全体の利益が減る

演習ステップ

  1. 粗利（1個の儲け） を計算する: A = 1,000−500 = 500円, B = 800−400 = 400円 → 1個あたりではAのほうが儲かる
  2. ボトルネック1分あたりの儲け（スループット） を計算する: - A: 500円 ÷ 10分 = 50円/分 - B: 400円 ÷ 5分 = 80円/分 → ボトルネックの時間で見ると Bのほうが儲かる
  3. 8時間 = 480分で、Aだけ or Bだけを作るときの全体利益を計算して比べる
  4. 結論: ボトルネック（制約）の時間という「限られた資源」を、1分あたりの儲けが大きいBに使う
  5. 5つの集中ステップ（Unit 6）: 制約（機械）をどう活用・強化するか
  6. Teach-Back

ヒント

  • 価格や1個の粗利で判断すると「A」だが、制約（ボトルネック）の時間で見ると「B」
  • TOCのスループット会計: 「制約の時間という貴重な資源を、何に使うべきか」で判断する
